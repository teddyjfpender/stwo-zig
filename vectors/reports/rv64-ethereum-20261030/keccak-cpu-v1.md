The receiver reconstructs preprocessing from its expected program and admitted execution/arithmetic policies. Exact request counts, call IDs, PC paths and RAM endpoints enter the public transcript and committed prefixes; they do not enter fixed columns. The test compares keys for zero versus two calls with different starting IDs at identical geometry.

The CPU authenticates ECALL's a0 pointer and a7 tag through ordinary register-state events and ROM decode. A positive typed header tuple contains call ID, local retirement tick and all eight pointer bytes. The bridge consumes the header and binds all 25 before/after RAM words to Keccak I/O. CPU register/RAM state and bridge RAM terms use the same original 20-field relation. One aggregate claim closes these effects, Keccak truth tables and the shared byte provider against expected public register/RAM endpoints. Balanced false header/bridge claims still fail component verification. Multiplicity traces are committed before lookup challenges, and the combined roster checks field-characteristic query budgets before allocation.

The fixture executes DIVW, SD, ECALL, LD, ECALL, LD, AND and SRA. It reuses a high 64-bit pointer across a page boundary and merges ordinary load/store clocks between service calls. The focused gate also tests allocation failures and compares the complete proof bytes for a retirement journal versus a 48-byte compact tape whose global clocks start at 2^40. The compact input is projected through immutable decoded ROM, without execution replay.

This is a public-cell boundary control profile. It does not prove an entire Ethereum block, private RAM hash roots, continuation between batches, or the Rust validator's input/output binding. No whole-block timing or peak-memory claim follows from this small fixture.
