# OP recursive-root admission review

`pure_p2_op_root_receiver.prepare` reconstructs the complete native Inventory and source bounds from independently admitted software, request and immutable setup authorities. It reconstructs the nine-coordinate global manifest from exact ordered worker metadata, without re-verifying native PCS or local-GKR proofs. Each CPU local receipt remains a pending commitment until its complete recursive leaf authenticates it.

The helper computes the exact CPU, catalog and Miller public-frame words using the same source helpers as their recursive statements. It hashes all words to the expected ordered leaf output vector. It checks local truth/SSA closure, source-specific global claim extraction, and separate RAM/KIO/Wire zero sums with absent-relation rejection. A balanced claim sum alone never authenticates a worker.

Two native-only policy obligations must remain explicit. CPU INIT/TEARDOWN claims are recomputed from the public cells and the manifest-derived RAM challenge, using the existing CPU receiver authority. Omitting that check permits balanced forged boundary claims. Production also requires a freshly pinned expected-image owner: its identity and output address/expected 43 bytes must match the admitted authority, and `Terminal.require` is repeated in the root receiver. This enforces its independently pinned absorbing terminal PC, halt flag equal to 1, output length 43, and expected output. Earlier native completion hooks provide no substitute. Generic source fixtures use an explicitly test-only preparation entrypoint; missing image policy fails closed on the production entrypoint.

`Plan.verifyRoot` accepts a concrete source Topology rather than an arbitrary proposed verifier key. Its leaf authorities originate in typed CPU/catalog/Miller source factories; it independently derives adjacent-pair fold keys and carries odd nodes unchanged. The helper checks execution identity, complete count and every leaf's ordinal, source-key identity and kind against its freshly reconstructed Inventory, then checks profile and nine outputs. Only successful physical verification against the expected canonical tree digest authenticates the prepared sidecar claims. No key decoder or native-child re-verification belongs in this step. The caller must use the actual source-derived topology constructor, never construct a handle around bundle-controlled authority.

Three filtered ReleaseSafe tests pass. Controls cover missing/duplicated/reordered leaves; wrong execution, ninth manifest coordinate, output, output wrap/missing word, image identity, CPU endpoint, omitted truth and native key; oversized claims; wrong topology coverage/profile/native identity/kind; balanced forged public boundary claims; and unclosed Wire debt. A balanced service forgery changes both expected leaf outputs and the expected final tree digest. Its rejection by an original physical root, valid same-profile algebraic key substitution, and actual pinned-image halt/length/PC negatives are required in the concrete end-to-end collector gate. They are not claimed by these preparation tests.

The helper alone does not accept an execution. The actual collector/root proof integration remains a separate gate. Security wording remains 128-bit security target under documented assumptions, with security_qualified=false.
