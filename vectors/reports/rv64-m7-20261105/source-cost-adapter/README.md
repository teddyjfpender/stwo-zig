Status: **real typed adapter/geometry gate PASS; admission-reserve semantic gate PASS. No GPU or full-proof qualification.** Root's Source ledger/runtime guard are separate dependencies and remain default OFF.

The new adapter consumes a borrowed `DeviceSourceStage.Request` without moving CPU/JALR or calling `Headers.take`. It derives layout words from actual Metadata, compact-record/seed, MAIN/ROM, family Fact, memory Event/Cell, and bulk/sponge public ABI types. Bridge input stride comes from the production encoder applied to one initialized synthetic record; it is not a copied fixture constant. `Tail.validate`, geometry LS/D64 splits, actual bulk/sponge row functions and setup logs determine every role/count. Scope/program/epoch/metadata/ROM shape and all advice indices are validated before returning a plan.

The full MAIN log list is checked **in canonical column order** against `setup.logs(1)`: core→bridges→bulk→sponge→DWORD→ZBB. Actual GPU allocation order differs (DIV output first; ZBB before DWORD). Root's `Plan.list` is a typed allocation/lifetime inventory, not launch order; its guard must compare the multiset within source phases. CPU projection retains its separate ordered event plan. The adapter binds the scope statement/fixed identity, program identity/profile, geometry and public operational dimensions. The independently authorized scope statement remains the authority for public RAM content; this adapter does not turn caller-selected scope bytes into proof authorization.

Root's mandatory runtime guard must cover every Source/TC allocation before mutation and preserve the audited compact-input join/release seam. It must also freeze the TC schedule, account existing physical retention, and retain new coefficients until actual worker destruction.
