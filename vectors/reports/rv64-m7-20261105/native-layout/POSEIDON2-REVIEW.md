# Independent scoped review of Core Poseidon2

Reviewer: OpenAI Codex, native stream. Evidence: read-only source review of `cbc689434`; existing test/receiver/memcheck results were supplied by the integration owner and were not rerun by this reviewer. This is not a security audit or whole-protocol acceptance.

The qualified QM31/OM31 framing has no identified blocker in this review. Raw u32 values are encoded as two16-bit field limbs, preserving values including p and2^32−1. The sponge uses additive absorption, a mandatory1 marker including an extra block at exact rate boundaries, separate leaf/node/mix/draw/PoW domains, and canonical nine-M31-limb output. The field degree enters the channel IV. Binary magic and JSON protocol names distinguish Poseidon from legacy Blake, and commitment, FRI and path hashes reject noncanonical limbs. PoW tests low bits of a canonical M31 word with a maximum30-bit difficulty, avoiding its guaranteed top-zero bit. CUDA numerical kernels reproduce this framing; no production CUDA PCS ABI or GPU PoW qualification is implied.

One source issue was found: the original `poseidon2_profile.ForField` named every secure degree except8 as QM31, giving unsupported field types the same suite identity even though the channel IV used their actual degree. Qualified QM31/OM31 callers were unaffected, and the proof wire already rejected other fields. The integration owner added exact-type compile-time guards to both channel and profile; this review inspected those guards in the integration worktree. The correction requires its own source-bound checkpoint and normal qualified tests before promotion.

The subsequent v2 worktree was inspected as a design delta, not as a qualified receipt. Its checked u32 draw counter, distinct type/profile name, v2 IV tag and new W02 wire identity avoid silently changing v1. Digest9 + counter2 + marker fits one rate12 block. The native and circuit source must both refuse draw-counter exhaustion rather than wrap, and source facts must cap per-transcript draws below2^32. GPU code must explicitly select v2; the v1 u64 callback cannot be reused under the new identity. v1 defaults and bytes need frozen golden checks.

Residual promotion gates: nine canonical limbs contain log2(p^9)≈279 output bits, so ideal generic collision work is≈139.5 bits, while capacity12 contains≈372 bits. Neither is a whole-system certificate. A source-owned work/ROM ledger must charge all Merkle, FS, PoW, bounded retries, class roots and recursion queries. It must separately account for ideal-output birthday collision probability Q(Q−1)/(2p^9), preimages Q/p^9 and FS bad-event unions rather than reuse a raw-Blake256 budget. Canonical M31 low-bit query draws differ slightly from uniform32: for k≤30, maximum residue probability is2^(31−k)/p. Secure-field coordinate draws are uniform over M31 only in the stated algebraic-RO model; the previous raw-u32 reduction factor must not be silently carried over. The permutation/parameter assumption, sponge reduction, algebraic PCS/GKR reductions and repeated adaptive transcripts remain explicit review obligations.

Native D2 and a Poseidon suite cannot be inferred from equal PCS numeric parameters. Receiver-owned selection must bind hash suite/version, field degree, sampler, AIR/GKR roster, source layout, PCS parameters and retry budgets in FIXED/VK/manifest authority. A mixed migration that keeps raw-Blake GKR or canonical chain digests must name that mixture explicitly. No RV64 Poseidon proof, all-Poseidon transcript, new on-chain wrapper or performance improvement is certified here.
