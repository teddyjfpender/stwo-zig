# Independent source review: request-boundary retirement and assignment graphs

Reviewer: proof-formats stream, 2026-11-05. Read-only review of Root9531c5c16954573aa052746d88c539fd79771388 and the matching128-oracle ABI source. No Root source mutation, build or additional GPU request was performed.

Disposition: no blocking lifetime/refcount or transition-timing bypass found in the reviewed paths. This is source review, not performance or complete-production qualification. Promotion still requires the matched final driver/runtime four-request M6 byte-parity and fresh-receiver gate; it cannot be inferred from this review.

* Phase retirement (`pcs_native.zig:143`): the context refuses an active block or retained request scopes, checks budget stability, audits all native request-lease kinds and immutable borrow accounting, then submits retirement on the serialized owner thread. Immutable entries are released only with users==0; the native release rejects outstanding immutable aliases. The second audit precedes publishing active_block. The native PCS trim synchronizes and releases retired upper-cache blocks only, preserving active planes, domains and managed leases. The explicit refusal when global admission is enabled prevents this unintegrated combination from silently bypassing that planner.
* Replay (`assignment_graphs.zig:56`, `circuit_fill_chain.cu:230`): mutable values/status still pass the mutable-lease borrow path. Tasks, ends and optional indices pass complete native descriptor validation, including context token, allocation generation, shape, kind and current scope alias. Native launch revalidates the managed ranges and updates every node's complete job/ends arguments before cudaGraphLaunch. Cache entries retain only CUDA graph metadata. Dormant old pointer values do not own allocations; the next launch rebinds them. `outer_assignment.zig:966` joins before status readback and request-lease retirement; owner callbacks also synchronize before returning. Metadata eviction/replay therefore does not race an earlier launch on the reviewed serialized path.
* Cleanup (`assignment_graphs.zig:129`, `pcs_native.cu:563`): ordinary synchronous submit is attempted first. Successful healthy cleanup does not poison the session, so later healthy destructors remain callable. Only a refused/failed ordinary callback falls back to terminal cleanup; that path joins before/after destruction, keeps poison set and preserves the original error string. Handles already destroyed are nulled before a fallback can retry. If both cleanup routes refuse, the code reports fatal service status rather than replacing the proof failure with a destructor panic. Remaining allocations are owned by final context destruction; this is a terminal-error path, not continued service eligibility.
* Measurement (`resident_batch.zig:238`): the request timer now starts before all beginBlock callbacks and ends after all endBlock audits. `phase_transition_ns` is an included subinterval. Setup/class persistence remains separately timed off the request wall, as before; it must not be added to or hidden inside a graph speed claim.

The Zig ABI and native headers agree: max_oracles128; BatchState61+33*128=4285words; GkrState2580words; alpha/lambda/seed/claims/point offsets280/288/296/308/2356. Native static_asserts cover the physical layout. This signoff applies to the pinned128-capacity runtime, not an arbitrary older64-capacity library with the same symbol names. `outer_gkr/profile.zig` retaining a conservative64-instance class ceiling is a separate format bound, not a host/CUDA state-layout mismatch.

Nonblocking claim limits: PCS trim is an optional looked-up symbol and logs `pcs_trim_api`; the selected runtime/gate must establish its presence before claiming both caches were trimmed. CUDA graph metadata is deliberately retained and is not a managed witness lease, so source review alone does not establish that the prior headline warm OOM is fixed or that all physical memory is admitted. CUPTI/NSYS graph-kernel coverage must be established separately before reporting complete GPU-seconds. No graph latency win, planner-combination support, or new proof format is promoted by this review.
