# Experimental SegmentV2 public-I/O binding

Issue [#228](https://github.com/teddyjfpender/stwo-zig/issues/228) concerns application I/O claims in the typed SegmentV2/V3 proof path. The existing `STWESG31` wire authenticates sparse RW-memory `(address, value)` pairs and the span statement. It does not retain `WordRole`, input start/length, output-length address, output-data address, or output bytes. Thus the wire alone cannot determine which memory words are application I/O or derive the span's edge digests. The native V2 core projection clears its V1 `io_entries`, so the inner VM proof does not add that missing relation.

`segment_public_io_binding_v1.zig` is an opt-in native verifier profile. A caller supplies an independently trusted ABI layout and expected byte strings. Its new digest domains are `S2I1` and `S2O1`, distinct from the existing V1/V2 hashes. Each preimage starts with version 1. Input then encodes its start address, exact byte length, and little-endian packed words. Output encodes its length-word address, data address, exact byte length, and packed words. The length makes trailing zero bytes unambiguous. Every unrestricted `u32` is split into two canonical 16-bit M31 limbs.

After a native proof capture succeeds, `validateVerifiedCapture` revalidates that capture and then checks both complete-job edge digests against the versioned encoding. It requires zero `public_io_state` at all four machine-state occurrences. For a first segment it compares every expected input byte with the authenticated entry sparse snapshot. For a final segment it compares the output length word and every output byte with the authenticated exit snapshot. It returns explicit input/output coverage flags; a complete-job consumer must verify all needed segments and require both flags. A separate native construction guard checks the same external I/O against the runner result. The focused regression uses a real runner with nonempty input and output and rejects changed input, output, length, digest, and I/O state claims. The CPU integration test exercises the helper on genuine native V2 captures and requires both endpoint coverages.

This profile is not activated in the default V2 verifier or V3 recursion. Production recursive activation requires a versioned verifier input that supplies the trusted ABI and expected I/O, plus AIR constraints (or an equivalent verified child-proof boundary) for the digest preimages, exact sparse-memory byte lookup, output length, and zero I/O state. The recursive parent must carry the same expected I/O identity across all leaves. Until that relation is implemented, a successful unprofiled V2/V3 proof must not be reported as proof of application I/O bytes.
