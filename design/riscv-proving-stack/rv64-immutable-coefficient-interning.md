# Bounded immutable coefficient sharing between whole keys

The full beta2 qualification retained 29 geometry-specific fixed keys: 7.386 GB live and 9.372 GB peak. Their logical native coefficient streams total 5.665 GB, before Merkle/descriptor overhead. Whole-key identities remain necessary because ordered columns and geometry affect authority. Reusing their common native coefficient payloads does not require uniform padding, a new proof profile or weaker identity checks.

The beta2 fixed cache now owns an existing `FixedNativeCache` under the **same** `SharedHostBudget` as its whole-key trees. Its retention cap does not authorize a second allocation budget. Each independently derived whole-key identity still hashes the trusted ordered source coefficient values. After native sealing, the cache interns owned coefficient planes by content digest, log/length and exact value comparison. Repeated immutable content shares one owned copy. A digest collision never substitutes different values. Originals remain separately owned, so an illegal mutation of the borrowed trusted source cannot mutate the candidate's cache copy.

The coefficient cache owns no retained LDE. It runs after the existing seal has extended and hashed the key. Whole-key Merkle trees remain separate; all interpolation/extension work still occurs. Therefore this slice targets retained memory and copying, not repeated FFT elimination. Setup-time and allocation savings require an actual-inventory measurement.

The tree's shared-owner allocation is reserved **before** interning can transfer custody. A constructor-only helper requires exactly one reference, the original allocator, and no already interned backing token. It updates the unpublished owner's tree and refreshes the outer metadata without a fallible step afterward. This is an exclusive-construction contract, not a general way to mutate published shared trees. No key/lease is published before the call returns. Acquiring concurrent aliases during construction violates the contract.

Interning itself performs all allocations and collision/capacity decisions before adopting or releasing payloads. On allocation failure the tree and native entries remain valid; no payload is transferred before the final nonfallible publication. Whole-cache descriptor capacity may have grown during earlier reservation and remains bounded. Cache, source and caller handles may be released before appended PCS trees: their shared native backing token and original allocator budget leases preserve custody until the last physical tree closes.

Tests cover two distinct whole-key layouts sharing one exact plane while keeping a changed plane, root and ordered identity distinct; source authority checks; candidate/source pointer separation; all allocation failures; source/cache/key release before appended OM trees; rejection when another tree lease exists; rejection of double interning; exact collision handling; and unchanged pinned beta1/beta2 roots. Canonical bulk identity hashing is a separate qualified optimization. Its actual 29-key A/B showed only a ~2.1% setup difference within variance, so it is not presented as a substantial speedup.

Before considering prepared fixed-provider LDE reuse, profile actual 29-key setup to distinguish extension FFT, leaf hashing, source identity and original key preparation. Any further cache must remain immutable-provider-only, explicitly bounded, independently validated and separately measured. This document makes no whole128 or GPU throughput claim.
