# Explicit OP-native complete-block route

`zig build rv64-op-native -Doptimize=ReleaseSafe -j1` builds an isolated experimental CPU entrypoint. Its commands are `capture CONFIG OUT [RESOURCES]`, `prove CONFIG OUT [RESOURCES]` and `verify CONFIG OUT [RESOURCES]`. The receiver's config pins the ELF, input, ELF-derived ABI symbols, absorbing terminal PC and exact 43-byte output. The execution profile must be `ethereum_services_op_v1`; old Ethereum request loaders continue refusing it.

The immutable image uses an explicit `ProgramAuthority.initForOpWord16` owner. It preserves historical v2 byte-ROM custody without admitting OP in the byte AIR, and presents the distinct OP execution-ROM authority to Word16. Existing `initWithRom` guards remain unchanged. Direct capture separately pins and loads a mutable execution image, runs the real service session and discards each compact tape after its ordered RAM-ledger append. The runtime derives CPU geometry and service counts from capture; it never imports an old ABI or zeros the OP service count.

A complete source-bound inventory precedes proving. CPU, inherited truth and Miller providers share the same two-phase manifest. Native CPU and truth fixed classes are deduplicated by immutable source geometry, independent of request counts. MAIN is constructed and committed once, then coefficients and Merkle layers are parked through the source-bound P2 store. Stage two restores one worker at a time and retires completed workers. A synchronized shared host budget covers runtime allocations and restored mappings; disk and simultaneous mapped payload have independent hard caps. This initial reference coordinator is sequential and has no performance claim of parallel scheduling.

Publication writes `native-op.json`, `cells.bin`, `native-op.bin` and timing. The separate `verify` process freshly loads the pinned image, preflights source bounds, rebuilds source/P2 keys, derives exact statements and manifest, verifies every local GKR and physical proof, closes RAM/KIO/Wire, then reads halt, length and output from the authenticated terminal cells. Producer-declared geometry chooses admitted cost; it does not replace source authority. No acceptance bit in a file is trusted.

Block 120794432 passes end to end with the final canonical guest: 796,406 instructions, one CPU proof, one Keccak truth (338 sponge permutations), one SHA truth (34 calls), 29,884 public RAM words and a 6,909,628-byte bundle. A fresh process accepts it. In the ordinary-layout ReleaseSafe correctness control, native proving took 24.271 seconds, producer process wall 28.61 seconds, and fresh receiver process wall 4.63 seconds. Producer peak RSS was 3.595 GB. These are first complete native correctness measurements, not a claimed speedup, recursive result or heavy-block qualification. The earlier independently qualified v3 GKR compact/pair/LS-D64 architecture must be carried onto OP before a heavy performance run.

Production CLI admission and certified whole-protocol security remain closed. The candidate uses the label **128-bit security target under documented assumptions**. Recursion and heavy-block qualification remain separate gates.

The native runtime now carries the compact OP GKR representation qualified by the complete mixed fixture: fused CPU tail, U8 pairs, LS-D64 and compact decode. `Program.makeCompact` runs before producer capture. Fresh reception consistently selects compact representation from all CPU declarations (mixed representations fail) before reconstructing the source program. Historical ordinary-layout bundles remain valid correctness controls under their distinct geometry-bound keys.

Optional native recorders preserve protocol bytes and old null defaults. Each worker exposes MAIN and INTER commitment preparation, composition, FRI, sampled values and decommit stages; the coordinator separately scopes source construction, local GKR sealing, parking, restoring and stage-two completion. Process timing also separates pinned image/program setup, capture, fixed setup/admission, stage-one/manifest/stage-two and publication. `check-rv64-op-native` is a semantic-only build target (`-fno-emit-bin`), avoiding LLVM emission in the development loop.

`Bundle.verifyWithHooks` may deliver typed borrowed CPU, catalog and Miller verified captures to a recursive leaf producer without repeating native verification. A fragment callback authenticates only that fragment: its artifacts remain pending. The returned `Closed` owns all decoded stage-one proofs, the manifest and global claims, through application completion. `Runtime.verifyDirectoryWithHooks` invokes its final completion callback only after all native proofs, zero-sum closure and the independently pinned 43-byte terminal output pass. Native capture, encoded-proof and source pointers must not escape callbacks; durable leaf outputs must own their storage. A failed callback aborts reception. These interfaces alone do not qualify a recursive root.

The real-artifact hook gate is `OP real native receiver capture hooks finish only after physical closure and terminal`, selected from `test-riscv64-op-native-join`. Set `STWO_OP_NATIVE_HOOK_REQUEST` and `STWO_OP_NATIVE_HOOK_BUNDLE` to the pinned config and qualified bundle; otherwise this optional gate skips. It accepts identical native bytes through null and typed hooks, checks exact source statements/roots/ordinals/capture shape, and proves callback error cleanup. A corrupted last physical proof fails after earlier successful callbacks. A test-only mutation of the borrowed HALT cell after CPU verification fails at the terminal gate after every fragment callback, and the completion callback never runs. Every case returns the whole-runtime requested-live count to zero. These are ordering/custody correctness tests; their timings are not performance receipts.

`Runtime.withSourceDirectory` factors the same pinned-image, bounded metadata/cells, source bounds, immutable keys, complete inventory and terminal *policy* checks into a source-only callback. It never opens `native-op.bin` and performs no native GKR/PCS verification. Its `SourceDirectory` is borrowed and grants no authenticated execution: a root-only consumer must verify its final root and bind all public/global claims before accepting it. Full native reception uses this same loader and still checks terminal RAM again after physical proof verification and fragment callbacks.

Capture-only mode also writes `native-op-cost.json`: active versus padded role rows and source-derived widths, captured owned payload, actual requested-heap snapshot, exact aggregate native MAIN coefficients and a conservative P2 Merkle/disk bound. Truth Merkle estimates use an explicit log16 local-table floor. This is a planning observation, not complete runtime admission or an RSS promise; fixed setup, GKR/source scratch and later restored mappings remain bounded by actual synchronized budgets.

The source-only callback is physically qualified against the same real artifact with `native-op.bin` deleted: metadata/cells/key/source-policy reconstruction succeeds, no fragment or completion callback runs, and requested live allocation returns to zero. The supplied shared allocator's hard limit must not exceed `Resources.live_bytes`; a mismatched larger allocator is refused before source loading. Prover-specific resource fields (parking, numerical GKR, generated interaction buffers) are not admission claims of this source-only helper.
