# CPU services worker: OM local GKR and physical global relations

The explicit `Manifest.PROFILE` route now has a concrete CPU-worker producer and
fresh receiver. It preserves each original MAIN span once, replaces its local
LogUp inverse traces with authenticated GKR Eq/prefix binding, and retains RAM,
Keccak IO and secp Wire as separately authenticated OM31 classic obligations.
The legacy Ethereum/Q route is unchanged.

`cpuStatement` streams the trusted program identity, geometry, bridge roster,
request endpoints/register clocks, public RAM cells, call spans, and PCS profile
into a deterministic digest. The receiver reconstructs it and the local roster;
no producer declaration chooses which constraints or relations to omit.

Stage one adopts MAIN through the existing owned streaming committer and cached
immutable FIXED tree, then derives a local child from durable narrow relation
metadata. The child transcript binds its actual MAIN root. Stage two requires an
independently verified complete manifest, produces bounded inverse/prefix planes
from saved RAM/bridge metadata, mixes every physical claim, and proves the joined
MAIN/local-binding/global system. Header allocations and shape validation precede
one no-copy INTER ownership transfer. The receiver decodes a fresh physical proof,
checks FIXED/MAIN roots, recomputes INIT/TEARDOWN claims from independently
admitted public cell lists, verifies all roles, and returns verified global debts.
It does not call an individual shard a complete execution.

The physical geometry is independently sized per role. Absent global fields have
no claim slots; the receiver cannot accept an arbitrary compensating debt. Global
relations close separately only after every CPU and truth worker has verified.
All secure coordinates, challenges, prefix columns and claims are degree-eight
OM31. This describes functional construction; a whole-protocol 128-bit claim
requires the separately maintained security budget and production admission.

`spillMain` / `restoreMain` reuse the qualified field-neutral retained store at the
stage-one barrier. Compact MAIN can be parked without a second witness or FFT
replay. The store's explicit byte admission and lifetime remain authoritative;
parking does not make retained RAM/bridge metadata free. Full-block orchestration
must spill MAIN and retire local-only metadata instead of retaining every worker
on a 64 GB host. These fixture gates do not establish a full-block memory bound.

Qualification exercises the captured two-shard K/ADD/DOUBLE execution: original
MAIN arithmetic, local child and manifest, genuine global planes, mixed-height
compact OM PCS, decoded fresh receiver and explicit remaining debts. Mutation
gates cover an eighth-coordinate public RAM claim, statement, physical root and
truncated claim vector. The parking fixture checks unmapped residency and root
preservation before restoration. No speed or complete-block claim follows from
these tests. Full multiworker execution closure is the next integration gate.

The worker also exposes `retireLocalMetadata()` after a successful seal. It is
idempotent in that phase and frees local CPU/ROM/ALU/BINARY/SHIFT/JALR/MUL/DIV,
tail, table and histogram owners. Only memory and bridge sources survive for
global challenges. Explicit teardown state prevents re-reading or destroying
retired owners. The qualification fixture invokes retirement before MAIN parking,
then proves and freshly verifies both shards. Early stage-one allocation failure
and retry after early stage-two allocation failure are exercised; this is not an
exhaustive full-worker allocation-failure sweep. Component and numerical helper
sweeps remain separate evidence.

Fixture PCS settings (`pow_bits=0`, blowup log1,12queries) are deliberately small
functional controls and carry no production128-bit claim. Production policy must
supply and admit its independently reviewed PCS/security profile.
