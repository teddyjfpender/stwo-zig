# Reusing shifted-row address metadata in OM truth composition

The actual block receipt `fullblock-capture-two` spends 30.912 and 31.862 seconds in the two Keccak composition stages. Their eight-worker lanes record about 190 user-CPU seconds each, so this path is already parallel rather than suffering the earlier null-pool problem. The original receipt does not split these totals into FFT and constraint-row evaluation.

The packed truth sampler recomputed a bit-reversed circle index for every shifted column and lane. A Keccak row needs four shifted views of 1,600 state columns. Those accesses share only 64 distinct row addresses per packed 16-row block; the old sampler could repeat their computation 102,400 times before header and prefix accesses. The optimization computes these addresses once into a 576-byte row-job-local cache, then gathers the same immutable current/previous source values in the same lane order. It neither caches field values nor expands additional columns.

The four explicit cached offsets are -2, -1, +1 and +2. Each address comes from the original core circle-offset authority, and each target is checked to belong to the current coset or its xor-one neighbor. Missing previous-column buffers still reject. Offsets outside the cache retain the original checked sampler fallback. A future mask change cannot silently select a different index rule.

A pure test compares every cached address against the scalar authority over all blocks at logs 5, 6, 9, 12 and boundary blocks at logs 16, 18, 26, both 2n/4n splits, every coset and lane. The dedicated truth-parallel suite also retains packed/scalar equation comparison, bounded-workspace allocation failures, and a pinned five-proof service fixture that agrees between serial/pool execution and freshly closes all global claims. The first attempted filtered gate used the wrong root; the no-selected-test guard rejected it. Qualification uses the actual `test-riscv64-truth-parallel` root.

The existing optional `STWO_ZIG_PROFILE_OM_DOMAIN` flag now reports truth preparation, FFT and row totals separately. Its absent/default path makes no timing calls. This is telemetry only and is not included in the statement or transcript. Actual matched-prefix measurement is recorded separately; source inspection alone does not establish a speedup.


The matched four-CPU/three-truth prefix uses identical source and optional phase instrumentation except for the shift-map sampler. All ten authoritative artifacts match byte-for-byte and both fresh prefix receivers accept; this is prefix verification, not a completed Ethereum block. The log13 Keccak row stage changes from 0.47644 to0.41874 seconds, with FFT 0.07632 versus0.07641 seconds. Whole-prefix proving 35.95 versus36.11 seconds establishes no overall speed gain. This single pair motivates measuring the full log18 providers; it is not a repeatable full-block speedup qualification. The same-source patch, file hashes, resource policy, raw profiles and receiver outputs are retained with the receipt.
