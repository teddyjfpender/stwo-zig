## Exact namespace authority

`blake3_parent_rebase.prepare` derives identifiers from typed recursion-wire relation effects. All but two AIRs place identifiers in fixed columns. Original inversion MAIN[9] and linear MAIN[1] also carry circuit IDs. Their AIR schedule equalities are gated by `in_circuit` or `enabler`; inactive MAIN IDs cannot be inferred from an AIR constraint or a fixed schedule alone.

`arithmetic_fusion_rows.materializeIdentifiers` therefore uses the original selected-lane reservation/emission walk. Optional callbacks record inverse circuit IDs during the original node traversal, and linear IDs only where the original fusion walk actually emits an unreserved linear row. The original Plan is independently rebuilt against its authenticated Reference before emission. No invocation buffer, private arithmetic evaluation or inverse is created. Legacy row/fixed/count sinks take unchanged paths.

`recursive_fixed_namespace.prepareForArithmetic` accepts the original Plan/Reference/kind, reconstructs these arrays itself, checks exact inversion/linear row counts and canonical identifiers, then derives the same sorted namespace union and original namespace identity. It never accepts a proposed identifier array. The ordinary fixed-only entrypoint classifies the two MAIN exceptions but retains an explicit `MissingRecursiveFixedMainIdentifierPort` obligation. Unknown MAIN namespace layouts are rejected. A live original rebase comparison detects even an inactive MAIN identifier mutation. This comparison is a compiler oracle, not cryptographic authority.

The source/reference objects are independently admitted, immutable borrowed inputs. Neither namespace recipe nor graph identity can make a received proposal an expected verifier key.
