# Lazy missing GKR checkpoint layers

Stride-two storage previously rebuilt every missing odd layer before the first sumcheck round. With many instances this materialized a secure numerator and denominator for all instances together, imposing a large numerical peak. The opt-in checkpoint path now borrows each still-retained lower checkpoint and stores one internal oracle flag. No Layer, proof, transcript, receiver, or security-profile variant is added; the default dense route is unchanged.

The first sum gathers at most sixteen terms into bounded local arrays. Original packed adjacent-pair reductions construct only those virtual rows, then the original GrandProduct or generic LogUp range evaluator computes their contribution. Scalar tails reuse the original fraction-add authority. The first fold again reduces a bounded span and writes only the already-folded quarter-sized owned planes, through the original fold kernel. Thereafter it is an ordinary owned oracle. A constant lazy oracle computes only the two mask values.

The bank owns the lower checkpoint until the current GKR iteration ends. The lazy oracle is an immutable borrower; all row callbacks and constant-oracle mask consumers finish before the bank pops that checkpoint in the next iteration. First-fold output allocation fails atomically before modifying the borrowed source. Cloned lazy oracles own their lower copy and preserve the flag. No retained odd layer or expanded witness is created. The largest sum tile uses 144 secure elements (4,608 bytes with OM31), plus ordinary call/scheduler scratch, within the existing one-MiB helper stacks.

Qualification compares every polynomial, fold and mask to explicit materialization for Q/OM and all four input kinds, including signed multiplicities, padding, zero denominators, tiny constants, partial SIMD tails, three-worker and held-lease execution, malformed shapes, exceptional challenges, and clone ownership. Whole mixed-height checkpoint/consuming proofs compare exact proof/artifact/next-draw digests against the unchanged dense route and freshly authenticate terminal MLE inputs; exhaustive allocation failures cover both checkpoint APIs. External pinned-source and real CPU0 results are recorded separately. No whole-protocol 128-bit or full-block performance claim follows from this slice.
