# Optional pure-function tails in one CPU proof

`Geometry.alu_tail_log`, `binary_tail_log`, and `shift_tail_log` append independently sized truth instances to the existing CPU PCS. They reuse the existing ALU, BINARY, and SHIFT polynomial authorities. No CPU rows, wrapped proofs, execution passes, or protocol profile enums are added. Producer CLI flags are `--alu-ladder=19,16`, `--binary-ladder=19,18`, and `--shift-ladder=19,18`. SHIFT fact grouping remains the separate `--deduplicate-shift` choice. Defaults retain one instance per family.

The producer partitions an already captured, optionally grouped fact array at the full head capacity: `head=min(T,2^head_log)`, `tail=T-head`. An enabled native tail needs `0<tail<=2^tail_log`; otherwise the producer rejects before CPU transfer/materialization. This differs from LS, which requires an inactive last row and uses capacity `N-1`. Each provider writes its final MAIN directly from its own narrow slice. No larger witness is built and compressed. Full-family canonical multiplicity and mass checks precede slicing, so splitting cannot admit a combined mass of at least the M31 characteristic.

Pure-function truth membership does not prove a native one-to-one row census. The provider has no public active-prefix or unique-fact count. The native partition is a witness construction choice, never receiver coverage authority. A receiver binds independently chosen geometry, proves every present fact with its committed multiplicity, and closes the CPU's positive FUNCTION queries under globally disjoint operation IDs and a positive consumer mass below the characteristic. A present empty truth instance would be sound but wasteful; the native planner rejects it. Exact producer head fullness is not a claimed AIR obligation.

Both instances share the same FUNCTION13 challenges. ALU also shares U16; BINARY shares AND; SHIFT shares packed SHIFT and U16. FUNCTION multiplicity is carried into both slices unchanged. Physical table queries remain unit-weight and padding-inclusive: ALU20 U16 queries per row, BINARY8 AND queries per row, SHIFT5 semantic table plus9 U16 queries per row. Private histograms are merged before the shared table constructor; fixed tables and challenged dictionaries remain one per proof where the existing APIs allow sharing. Both instances retain strict denominator-pole checks, including zero-weight and padding facts.

The shape authority appends `alu_tail`, `binary_tail`, and `shift_tail` at ordinals18,19,20, after the existing LS tail17. Absent tails have zero columns and no component. Present tails use exactly the existing widths: ALU2/52/48, BINARY2/42/24, SHIFT2/53/36 for fixed/MAIN/INTER. Program and geometry determine the immutable fixed key; request counts, grouping, multiplicities and public endpoints do not. Components and custody iterate that single physical shape order.

Core schema4 and durable Bundle schema4 replace schema3. The canonical ledger appends ALU2, BINARY2, SHIFT3 fields at offsets38,40,42; `P.CLAIM_COUNT=45`. All global/service extensions derive that constant. Every omitted family tail must have its individual fields zero before acceptance; a balanced omitted claim cannot cancel a physical debt. Present ledger fields are bound into the transcript. Each existing merged-prefix component authenticates its complete physical aggregate; these additive bookkeeping fields are not new independently constrained relation totals. `P.ramClaim` remains only LS head/tail plus INIT/TERM RAM debt. Pure-function debt is never exempted by global RAM or service closure.

MAIN and INTER handoffs transfer each present allocation once. Absent-role private extras keep their ownership flag and are freed by the source owner. Constructor errors unwind private completed instances without consuming caller fact arrays. Existing narrow capture, scoped pool, prefix and native parallel formatter authorities remain unchanged.
