# Source-owned immutable CPU setup across requests

The explicit OP pure-P2 route can retain its independently constructed CPU setup between requests. This preserves existing source/key identities, statements, transcript and proof bytes. It does not load producer roots, deserialize keys or accept a producer cache. The first acquisition constructs the source setup and P2 commitment from a freshly pinned executable authority exactly as the uncached route does.

`pure_p2_setup_cache.Cache` owns a stable heap state, decoded program metadata, CPU setups, and exclusive parked FIXED templates. Lookup includes the independently derived executable identity, proof profile, execution/control profiles, and typed CPU/bridge geometry. A candidate hit additionally compares the exact executable words, addresses, profiles and complete geometry. Hashes are lookup hints. The retained program owns its raw executable views; no request `Image`, input, initial RAM, expected output, call span, statement, transcript or proof is retained.

Each acquisition returns a lease. The cache handle can release its ownership before leases retire; the state, files and immutable keys remain valid through the last lease. Borrowers and workers must finish before releasing their setup lease. The runtime holds one lease per distinct request class until all workers/callbacks retire. Each worker still uses the existing root-only stage-one view and bounded read-only FIXED materialization during physical completion. No wide FIXED tree is restored simply to hit the cache.

The cache requires an identifiable common `SharedHostBudget`. Its dedicated child budget covers cache objects, immutable matrices during bootstrap, retained metadata, file descriptors, and externally reserved restored mappings. Heap, disk, mappings, metadata payload and entry count have explicit caps. There is no global singleton and no automatic eviction or repeated construction hidden behind an entry hit. A full cache rejects another class. Caller-owned immutable setup and request allocation remain distinguishable while contributing to the common hard host limit.

The initial request admission deliberately permits one active request per cache. The configured immutable disk/mapping caps are reserved from the request's MAIN store limits, so cache growth cannot silently exceed the total declared quota. A second concurrent request fails closed and can be queued by its caller. Parallel workers within a request are unaffected. Multi-request concurrency will require subdivision of this same shared quota rather than independent full-size stores.

The opt-in APIs are `Runtime.produceDirectoryWithCache`, `Runtime.verifyDirectoryWithCache` and `Runtime.withSourceDirectoryWithCache`. Historical entrypoints retain independent cold construction. A receiver creates its own source-owned cache and bootstraps from its pinned source; a prover's cache is not an authority transfer.

The actual small-block gate proves block 120794432 twice through the same source cache. Both 7,048,980-byte native bundles equal the earlier qualified compact bundle byte for byte and a fresh independent receiver accepts. Setup/admission is 3.001059292 seconds on bootstrap and 0.025041292 seconds on the hit. One entry remains, with 181,469,184 parked bytes and 53,032,162 retained requested heap bytes; no mappings or request leases remain. Native proving itself is 14.126/14.651 seconds in those two runs. Other correctness work ran concurrently, so whole-run times are not a controlled prover-speed comparison. Cache teardown returns the common heap/external counters to zero.

The checked small fixture rejects reuse for different executable words, proof profile and geometry, and exercises entry/resource caps plus lease survival after both source-image and cache-handle destruction. A real metadata final-register mutation is rejected even when immutable setup lookup hits. The complete heavy source-preparation result of 421.689 seconds remains a cold measurement; no full-heavy cached proving speedup or all-36-class cache admission has yet been measured. Root distributions are exposed by scalar-only diagnostics for a future necessary source pass, without rerunning heavy bootstrap solely for statistics.

A separate empty receiver-owned cache also bootstrap-verifies the retained artifact and then verifies it again on a hit, importing no producer cache or key. Setup/decode is3.075243459s cold and0.129959459s warm; physical native verification remains1.359/1.356s. A changed request frame is rejected on the hit, and cache teardown returns requested heap to zero. These costs distinguish reusable source authority from the still-unoptimized physical verifier.
