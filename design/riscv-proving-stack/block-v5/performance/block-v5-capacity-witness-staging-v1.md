# Capacity witness-once proposal and staging

`block_v5_cpu_capacity_root_proposal_v1` owns a genuine `NativeCapacity.Proposal` in its `physical` field, plus first/last cycle, checked metadata bytes, native resource limits and a capacity catalog candidate. It owns public IO storage once. `bind` independently checks exact span and ordinal, public digest, fixed root, template and catalog candidate before using the real capacity proposal identity. This is first-pass metadata, never a verifier receipt.

The legacy `block_v5_native_columns_stage_v1` keeps its public API and delegates owner reconstruction to `block_v5_native_columns_rebuild_v1`. The capacity stage uses the same kernel to load bounded, hash-pinned original main cells, clone public IO, alias opcode/clock views and regenerate lookup/clock counters from the committed cells. Stored counters or activity selectors are not accepted. Scope and column geometry are independently supplied, rather than inferred from the file.

`block_v5_capacity_native_columns_stage_v1.ForBackend.load` calls actual `Capacity.commitPhysical` once. `loadWithBasis` calls actual `commitPhysicalWithBasis` with an authenticated immutable producer basis. These kernels generate capacity fixed selectors and dynamic activity/count columns (or the genuine empty native frame), then commit the real PCS. The stage compares first-pass roots, template, public digest and identity. `Prepared.takeFirstRound` late-binds the actual `PhysicalFirstRound`, moving that PCS into the capacity producer without another commitment. The returned FirstRound must finish/release before Prepared releases its borrowed source owner. Errors before bind retain the PCS; a checked post-bind failure releases it, and Prepared still owns the source owner. Zig tokens must not be copied as owned values.

The first-pass collector APIs are `Root.ForBackend(B).collect(a,owner,config,profile,index,first_cycle,limits)` and `collectWithBasis(...,limits,basis)`. Limits include `native: CapacityProof.Limits` and a wrapper metadata byte cap. Capacity fused collection can use `&proposal.physical`; Native Stage `write` uses the full span wrapper. Shared Planning can expose a typed nativeMetadata accessor to preserve one authoritative shape copy. Driver/collector defaults are unchanged by this batch.

Source fixtures cover span/catalog/public/cap mutations, real typed witness-row and clock counter parity through capped files, original column aliases, copied public IO, empty-frame metadata, SHA/scope rejection and allocation cleanup. They create no guest execution, physical commitment, STARK, recursive proof or device work. Body-retention qualification must compile the actual default and capacity reconstruction, collection, fixed-basis and PCS-transfer paths. The agent ran formatting only. The source candidate is not a qualification of generated capacity proofs or canonical driver operation.
