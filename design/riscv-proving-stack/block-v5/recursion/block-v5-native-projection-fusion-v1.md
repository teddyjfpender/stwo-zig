# Native projection fusion v1

This describes the intermediate projection-only format. Canonical production
now selects [v2 projection and ordinary-memory fusion](../../../../autoresearch/notes/2026-09-24-ethereum-block-delivery/block-v5-full-native-projection-memory-fusion-source-v2.md),
with independently admitted typed absence and shared global consumers. The v1
scope and evidence below remain historical; v2 source integration does not
establish fresh complete proof acceptance or performance.

This source slice combines opcode ROM requests and all native lookup/state/register/auxiliary-clock partitions into one genuine PCS proof. The V1 arithmetic path remains an explicitly separate compatibility format. Canonical production source now selects the V2 projection plus ordinary-memory path described below. Complete block authority still requires every global provider and exact recursive closure. Sources are formatted; the seven-test nonproving equation/mask/API gate passed. No STARK proof or performance benchmark was run for this slice. Segment runs remain stopped.

The implementation lives in `prover/block_v5_native_projection_fused_{source,component,proof,receiver,stage}_v1.zig`. The canonical source schedule places all program slots first, then the existing typed native projection slots. Each slot keeps its own normalized four-coordinate LogUp prefix and scalar claim. The component uses the original program source or native typed-entry source, with the same exact numerator, denominator, mode selection and degree. All components use one independently derived composition split: the maximum required by their degrees, at least two.

`Proof.ForBackend(Backend).borrowFirstRound` borrows the two immutable native fixed/main trees through the existing shared-tree lease helper. `prove` commits all projection interactions as one tree and calls `engine.prove.prove` once. This produces one composition commitment and one FRI/opening transcript, rather than concatenating prior proof formats. A bounded 256 MiB/4096-entry quotient-column cache is shared by all source projection components in this call; fallback retains the original degree-checked local recovery behavior. Interactions still use four columns per slot: this slice removes duplicate PCS rounds, not the underlying independent bus equations. Larger shared composition degree may increase some component evaluation domains; no speedup or memory reduction has been measured.

The union main mask opens only the original selected columns, once, at the current point. Fixed columns retain their original empty opening vectors: independently fresh native admission supplies their authority. Each LogUp prefix opens current and previous values at the existing circle-domain shift. Separate claim vectors preserve the six table sums, registers-state, auxiliary clock RW memory, ordinary register memory and auxiliary register clock memory. Program requests retain an exact integer fetch census. No bus is merged into an undifferentiated authority scalar.

## Admission and ownership

`Receiver.InstancePin` contains the independently pinned native shape, lightweight public admission, native template/key ID and execution profile. `Receiver.instanceId(template_id,native_instance_id,index,canonical_slots)` derives a B5FP/version-1 program-request ID. The ordered B5SS roster must contain that exact ID and the same fixed/main roots as its execution entry. Existing B5PR program-request IDs are deliberately different; old artifacts cannot be relabelled and old receivers will not admit this new format.

`Receiver.ForBackend(Backend).verifyOwned(a,native_proof,fused_proof,index,pin,sealed,pins,entries,catalog)` consumes both actual proof objects on all paths. It independently reconstructs the source seal, catalog/public/template admission, slots, physical column logs and native instance ID. It fresh-verifies the native-v3 STARK with catalog admission internally, then fresh-verifies the combined projection STARK against those authenticated roots. The output is `Open{native,projections}`, with separate bus claims. Caller-created receipt structs never replace either verification. A truly empty logical projection is explicitly rejected pending the typed authenticated absence branch; it is not represented by a fake zero proof.

`Stage.ForBackend(Backend){sink}.hooks()` plugs into a lightweight warm producer callback without retaining a witness. The typed sink is `put_fused(context,index,*Proof)`: success transfers proof ownership, error leaves cleanup with the callback. The stage checks phase/config/template/admission/source-seal/catalog/ID equality and every leased column pointer, length and log size. It proves inside the live native first-round lifetime and checks that the native owner still has its original two trees afterward.

## Canonical V2 production integration (source only)

The V2 modules owned by the memory family combine these projection equations with ordinary packed-memory access equations. Nonempty RW schedules use trace trees `{fixed,main,access_witness,interaction}` and one shared composition/FRI/opening proof. Projection-only schedules use the real three-trace-tree format. A genuinely empty projection and RW schedule consumes no fused file; it still requires fresh native-v3 verification and exact independently reconstructed absence. No fabricated zero receipt replaces either AIR.

Assembly's `Program.addLightweightFused` derives the B5FP/version-2 ID from template and native instance IDs, native roots, access-witness root, execution ordinal, exact local/global frame, sealed register mode and both typed schedules. The existing ROM census is mutated exactly once. Producer's admitted `fused_program_requests` flag skips the separate program proof only after reconstructing that exact sealed entry. The canonical driver uses V2 Stage rather than separate program, lookup and ordinary-memory stages. V1 Stage does not set this V2 flag.

`Programs.ForBackend.verifyWithFusedMemoryHooks` receives independent per-execution `MemoryPin{frame,expected_events,witness_root}` values. It loads one V2 fused proof and one native proof, freshly verifies both internally, and passes scoped optional partitions to private global hooks. `Global` derives these pins from its own memory/public admission and routes the fresh memory partition into `MemoryJoin.onFusedNative` without invoking the old opcode loader. `TableJoin.onFusedNative` checks the V2 admission again, then closes the original six-table groups, per-leaf PC/state and register-window obligations using the separate fresh projection partitions. ROM closure retains public terminal boundaries and sparse caller requests. Final accounting and exact recursive admission remain unchanged.

Canonical transport appends family 14 (`native_fused`) without renumbering prior families. Its codec accepts only V2 `Proof{stark,claims,memory_claims}`. Independent policy derives both claim cardinalities, exact four/five commitment counts, root count, access root, column bounds, composition split and sample limits. The canonical policy emits no separate request, native-projection or ordinary-memory file. Old envelope families/IDs cannot be relabelled; the secondary census is checked before allocation. Store publication, loading and manifest snapshots share a mutex; worker publication must finish before deinitialization or manifest publication.
