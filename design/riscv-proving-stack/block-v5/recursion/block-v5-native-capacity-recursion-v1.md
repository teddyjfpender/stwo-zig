# Native capacity recursion v1

This is an opt-in, source-ready B5CT recursion path. It has not yet been qualified by an actual recursive proof or activated in the canonical block driver. The original NativeV3 routes and encodings remain available. Pure metadata/equation tests and object body retention are provided for serialized root qualification; this implementation makes no device, timing, RSS, or complete block claim.

`block_v5_native_capacity_recursive_admission_v1.Prepared` independently binds the capacity template/catalog, exact execution shape/public admission, external retirements, B5SS roster, security profile, limits, and owned PCS column logs. Capture admission rechecks those logs against the real capacity protocol. The producer takes the distinct capacity proof and its genuine fresh `VerifiedCapture`; it cannot accept an old NativeV3 capture or substitute a digest fold.

The composition circuit replays the original typed native arithmetic and interaction equations using the committed main active selector. It then checks all four active-prefix/count equations per shard in the original composite order. Every expected count is a public graph input. DEEP/PCS replay uses the actual composite masks, including current/previous openings for both added columns. Empty ordinary execution uses the real typed frame with public total/external count. Transcript replay retains B5CT/v1 framing and the exact shared universal draw prefix, commitments, claims, FRI, queries, and final channel.

The B5CT public bus and recursive protocol have distinct source circuits and identity/claim frames. They supply B5SS, template, instance, ordinal, fixed/main roots, PC compensation, open claim, and up to 257 shard counts with bounded `u32` indices. No changing count/root/instance is fixed in setup. The key context must match the public template and both recursive/child configurations must match the native security profile. Recursive claims close against this supply while the native global claim remains open.

`block_v5_native_capacity_recursive_stage_v1.ForBackend.publish` fresh-captures the borrowed real native proof, prepares committed recursive columns, proves with an optional bounded capacity specialization of the existing reusable setup cache, encodes and independently verifies the recursive proof, then transfers an owned artifact to a typed sink. Success consumes the artifact; failure retains it at the stage. Captures and recursive rows have one-instance lifetime. Cache entries retain only exact setup/fixed fingerprints and owned schedules; dynamic admission is rebound on every use. The artifact does not grant global closure authority.

`block_v5_open_child_frames_v2.fromCapacity` normalizes the actual new protocol's transcript and public supply for genuine nested OpenV2 equations. The existing exact forest/global receiver currently keeps its NativeV3 default policy. A typed capacity leaf adapter and independent capacity fresh receipts are required before canonical integration; fresh providers must still close every exported ordinary/program/memory/native lookup relation.

The narrow CPU-only root is `src/frontends/riscv/block_v5_native_capacity_recursive_test_root.zig`, filter `capacity recursion:`. It compares the symbolic recursive evaluator with the actual composite CPU point evaluator, checks mixed domains and active/count mutations, 5/7 and frame 3/7 graph reuse, the 257th public count, independent catalog/public/roots/config/log mutations, public-supply closure, and allocation-failure cleanup. `src/frontends/riscv/block_v5_native_capacity_recursive_codegen.zig` exports `stwo_capacity_recursive_body_gate` and retains actual publication, preparation, receiver, normalization, cache, and teardown bodies without invoking them.
