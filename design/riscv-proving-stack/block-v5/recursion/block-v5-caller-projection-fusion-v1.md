# Caller projection/access fusion v1

This source-only slice combines caller ROM, PC/state, six shared-table/register partitions and packed external-memory access into one genuine PCS proof beside the separate caller arithmetic proof. It uses the original SHA, Keccak and signer sources/evaluators. The isolated nonproving root passed 11/11 (including six transitive tests) in `/tmp/v5-caller-fused-nonproving.log`; actual producer/receiver/stage bodies were generated, but no STARK, guest/segment run or benchmark was executed. Canonical source integration is now wired and awaits its separate nonproving body/transport gate.

The isolated files are `prover/block_v5_caller_fused_{schedule,component,proof,receiver,stage}_v1.zig`. `block_v5_composite_projection_adapter_v1.zig` remaps existing three-trace-tree program/state/table components to `{fixed,main,access_witness,interaction}` without changing their equations, masks or quotient domains. `block_v5_composite_pcs_v1.zig` commits one interaction tree and calls the production prover exactly once, or performs one fresh verifier call. It does not concatenate proof bytes or replace proof checks with sums.

## Exact source and PCS grammar

The ordered interaction schedule is program slots, the same slots in state projection mode, authenticated typed caller table/register slots, then mode-filtered external access slots. Each program/state/table slot retains four normalized prefix columns and its own scalar claim. Access slots retain their original packed-transition, seven byte-part, universal-opposite and exact integer active-count claims. The common composition split is at least two and admits every independent projected degree; access/program quotient evaluation domains remain their original size. The first access component owns the union fixed/main openings. Keccak's full current and `+27` state masks are preserved. Each projection only inserts an empty access-witness tree and maps its interaction tree from index 2 to index 3.

`Schedule.init` independently validates the canonical Ethereum-v5 profile and admission, derives all placements/selected entry ordinals from the pinned statement, and reconstructs the exact mode-specific access roster. Its table receipt reports the original **all-access** arithmetic census, while the memory receipt reports the independently pinned RW census in register mode 1. Register table partitions remain separate from six provider-table partitions. The original `Owner.memoryPairCensus` proves the absence of an auxiliary caller clock-memory helper partition; no arbitrary zero is supplied for it.

The new B5CF/version-1 family12 identity binds caller key/instance, execution instance/ordinal, caller fixed/main roots, packed access-witness root, complete local/global Frame, sealed register mode, packed word ABI, all typed schedules and both exact event censuses. Family11 remains the original arithmetic admission; family13 retains its exact existing packed access entry. An old standalone program ID or separate proof cannot be relabelled as B5CF. The proof object is `Proof{stark,program_claims,state_claims,table_claims,memory_claims}` with five commitments. Every list cardinality and integer count is checked before component construction, all canonical secure claims are transcript mixed, and all three source roots/config must match fresh admission.

## Producer, fresh receiver and ownership

`Stage.lateBind(a,physical_proposal,execution_instance_id)!Bound` validates the existing value-owned physical caller proposal and derives new family12 without rebuilding an arithmetic witness, counter or PCS tree. `Bound` contains the same record/family11/family13 and new family12. First-pass counter bounds/snapshots and byte demand remain exact existing values.

`Proof.ForBackend.proveForCallerFirstRound(a,access_first,inputs,caller_first,frame,witness_root,sealed,pins,entries)!Proof` requires a live caller phase with exactly two trees, a separately owned access prefix with exactly three trees, exact config/profile/root/geometry/roster equality, and pointer/length/log equality for both immutable leased source trees. It recovers selected projection source spans once from the original caller prefix; it does not call `Profile.mainWitness` or replay execution. The existing access traces, committed integer witnesses and byte snapshots supply access interactions. Interactions are ephemeral and released after proving. Caller first-round ownership remains live and usable for its arithmetic proof.

`Stage.ForBackend{sink,frame,expected_witness_root,expected_byte_snapshot}.proveWarm` uses the shipped `CallerExternal.Prepared` recipe once, validates physical replay roots and exact byte snapshot, then publishes one owned composite proof. `provePreparedWarm` consumes an already made Prepared access prefix, avoiding a second recipe/commitment. `Sink.put_fused(context,index,*Proof)` consumes ownership only on successful publication; error cleanup remains with the stage. No source witness or PCS capture escapes the callback.

`Receiver.ForBackend.verifyOwned(a,caller_proof,fused_proof,index,Pin,sealed,pins,entries)!Open` owns both real proofs on every path. Independent `Pin` carries statement, total steps, execution/caller/key IDs, caller roots, witness root, Frame and RW census. Admission reconstructs the canonical profile/schedule/roster and checks the pinned key. The receiver freshly verifies family11 internally before verifying the composite against that fresh binding. `Open{caller,fused}` exposes separate scoped program/state/table/register/memory receipts; only its memory range array needs owned teardown. `verifyAfterFreshCaller` is the private hook seam for an enclosing receiver that just verified the base proof, never a detached authority API.

A missing caller is represented by `verifyOptionalOwned(...,null,null,index,null,...) -> null` only after the seal has no family11/12/13 entry at that execution index. The complete receiver must reconstruct its sparse Pin roster from the independent caller census. No supplied Pin permits either proof to be absent; no zero receipt or dummy empty STARK is produced. Current admitted SHA/Keccak/signer families all have real RW accesses, so a present caller always uses the real four-trace-tree/five-commitment format.
