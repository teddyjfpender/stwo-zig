# Actual CPU recursive-family publication

This source batch connects the existing seven typed recursive leaf families to
the actual capacity CPU driver. It is an explicit supplemental OPEN route:
`Driver.Options.recursive_families` defaults to `null`. It does not replace the
original complete CPU Global/Detached verification or issue `ClosedBlock`.
Default proof security remains the driver-selected profile (q70/pow26 in the
canonical product). No compiler, test, proof, guest, segment or device runs were
performed by the author.

`block_v5_cpu_recursive_sources_v1.Owner.create` takes the real Collected,
Assembly, and stable original native Prepared vector. It constructs exact
caller pairs, source-selected native fused companions, lane pins, range shards,
ROM and field-safe lookup group admissions. No roster is rounded to a power of
two. Genuine zero-RW lanes/ranges and native companion absence remain empty.
Strict lane mode1 is required for this supplemental route; default legacy
driver behavior is unchanged.

`block_v5_recursive_leaf_store_core_v1` adds source-only writer construction.
An unbound slot cannot publish or load. Each original recursive Stage has an
optional `on_template` callback after its original fresh verifier capture and
actual row-derived key construction. The typed callback checks that its
Prepared pointer is the retained source owner and binds one immutable owned
schedule under the existing slot cap. The callback grants setup metadata only.
The original recursive Stage still proves and freshly verifies the recursive
leaf before its original Store sink can publish it. Native fused bindings
constructed from the sealed execution entry are explicitly proposed links;
their zero unused native open-sum field is not a claimed or accepted native
receipt. Arithmetic/fused companion pairing remains mandatory above the leaf.

Production call sites are `IndependentFamilies.callers`, `memory`, `program`
and `lookup`, and the live native fused warm sink in
`block_v5_cpu_driver_common_v1`. Callers use
`proveStagedWithAdmissions` with stable catalog pairs. Every wrapper publishes
the genuine recursive leaf before forwarding the same owned original proof to
the existing base Store. Failure leaves base proof ownership with its original
producer. A failure after recursive publication aborts the driver and does not
publish a complete supplemental inventory.

After both the leaf queue and independent families join, the driver publishes
`B5RLOP01`, a bounded fixed-width OPEN file inventory. It contains the exact job,
common seal, family/index/file pins and proposed expected key IDs. It carries no
proof, source completeness, hierarchy or residual authority.

After the original Detached verifier succeeds, the supplemental receiver
reopens existing durable base proofs. `block_v5_cpu_recursive_template_derivation_v1`
freshly verifies those originals and reconstructs their real verifier rows,
key and schedule. `block_v5_cpu_recursive_receive_v1` compares proposed key IDs
against this derivation and invokes each family's real fresh recursive Leaf
verifier on the durable bytes. Caller arithmetic and fused proofs are loaded
together for matched original verification. No received artifact key or
metadata-file self-hash selects the expected key. A standalone process can call
this receiver with its independently reconstructed source Owner and fresh base
reader; the inventory cannot construct either authority.

Source admissions, source plans, stable caller pairs, original native Prepared,
Assembly and base Store outlive all publication workers. Driver defer order
joins workers/forest readers before releasing the seven Stores, their schedules,
source Owner, original Prepared and Assembly. The host budget is shared; no
replay, original PCS or proof clone is retained by supplemental Stores. Metadata
arrays, caller metadata, captured original verifiers, row preparation and each
proof remain subject to their existing independent caps. A fresh consumer keeps
one provider proof or one matched caller pair plus one reconstructed setup and
one recursive file live. Cold setup/row construction is repeated at fresh
reception; this cost is real, with no timing improvement claimed.

The remaining integration is actual heterogeneous/scoped topology admission
and source/public/global closure. The seven published policy sets are exposed
as immutable borrowed source/key schedules for independently admitted roster
construction, but this batch does not create a source-complete ScopeKey policy,
fabricate register/program compensation exports, or infer global residual
closure from file counts. The compact/public/wide protocol sources are unchanged.
Final canonical activation requires the assembled source/body gate, genuine
runtime qualification when authorized, and matched complete recursive closure.

The authored gate roots are
`block_v5_cpu_recursive_publication_test_root.zig` (legacy runner) and
`block_v5_cpu_recursive_publication_selected_test_root.zig` (selected runner),
filter `cpu recursive publication:`. They contain six behavioral checks and one
body marker retaining both actual Driver bodies, seven-family publication,
original setup derivation and fresh receiving. The fixture setup keys are
deliberately nonproof host admission values; no fixture asserts cryptographic
acceptance. Allocation failures, source pointer identity, sparse indices,
unbound publication, one-time binding, schedule caps, callback defaults,
framing/order/truncation/overflow are covered without proving.
