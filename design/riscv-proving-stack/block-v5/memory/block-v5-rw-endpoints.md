# V5 public final-memory custody

The endpoint provider preserves the existing sparse full-image BLAKE3 state-root semantics, including public input words. It classifies each address from the independently pinned memory layout; input and private RW endpoints have separate counts. Program-data endpoints reject until a raw-word ROM bridge authenticates them.

`block_v5_rw_endpoint_sources_v1.Pins` binds the independent initial-source plan, exact sorted-memory plan, expected final root, and endpoint file SHA256/count. The B5SS `rw_endpoint_plan_digest` commits that plan before challenge draw. Each endpoint record is address LE4, final global clock LE8, final value LE4. The records are strictly increasing by address and correspond exactly to memory-space first-touch keys. Untouched words carry forward from the independently pinned initial image; touched zero values remove sparse leaves.

A same-root endpoint sidecar opens the sorted-memory fixed/main commitments. At a key change, it emits the previous memory key's last clock/value. The linked predecessor supplies this tuple across independently sized instances. The global last row emits the last key's endpoint. Registers are omitted from this provider. Two inverse terms and cyclic sum/count prefixes constrain this projection; the byte-packed 64-bit clock has no field-modulus alias.

`block_v5_rw_endpoint_receiver_v1.verify` loads and fresh-verifies each endpoint proof, then the sorted proof under exactly the same roots. It also fresh-verifies all shared range shards and closes initial-source claims through the existing batch receiver. Only after those checks does it require the exact endpoint count and sum against the precommitted public file. Its return is scoped memory custody, with the sorted transition sum still open to execution closure. It grants no native, precompile, ROM, recursive, or complete-block authority.

The current verifier carries O(distinct touched memory keys) endpoint records plus the public initial sparse image. Root reconstruction is a public host computation, not a succinct final-root AIR. Register/PC/cycle/public-I/O continuity remains the responsibility of freshly bound native public statements and executed-span folding. Standalone proof projection receipts do not authorize sorted ordering; the paired block receiver verifies both proofs.

The focused fixture uses log8/log9 independently sized sorted instances, one shared range shard, a key change across the instance boundary, the global-last public-input key, and an untouched RW word. It tests corrupted file bytes and a substituted independent root before proof loading, and re-pins/re-seals/re-proves an incorrect final clock to test relation rejection after all fresh sorted/range checks. This is a scoped fixture with placeholder unrelated family entries, not a complete v5 block.

Validation: the focused ReleaseFast q8/PoW0 endpoint gate passed 4/4 tests. The combined separate precompile-arithmetic plus same-caller-root external-memory projection gate also passed 4/4, proving 103 SHA/Keccak caller accesses. Both gates are scoped; global native/execution/ROM/table closure and a complete v5 recursive receiver remain required.
