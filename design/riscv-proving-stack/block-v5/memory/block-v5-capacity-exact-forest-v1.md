# Typed capacity exact forest

This source-ready opt-in integration feeds genuine B5CT recursive leaves into the existing exact OpenV2 pair/quartet forest. It does not activate the canonical Global receiver/CPU driver and has not been qualified by a new STARK/forest run. Segment, proof, device and benchmark runs remain stopped.

`block_v5_capacity_exact_leaf_adapter_v1.Policy` contains an independently prepared capacity admission, a fresh capacity-native `OpenReceipt`, and independently pinned capacity recursive key/schedule. Its verifier checks actual capacity recursive proof bytes. Its normalizer preserves B5CT transcript/public count frames and the B5CQ claim frame. No old native receipt or key is relabeled. The scalar open sum is public expected data; it never substitutes for verifier equations or global provider closure.

Exact reception, bounded incremental staging and detached transport each have one shared implementation specialized by this typed leaf policy. Public original APIs continue to select NativeV3. `block_v5_capacity_exact_forest_receiver_v1`, `block_v5_capacity_open_forest_stage_v1`, and `block_v5_capacity_open_forest_manifest_v1` select capacity explicitly. The stage output/parent transport types and canonical manifest serializer are shared; proof authority comes entirely from independently supplied policies and keys.

The stage owns a duplicate of the capacity schedule with its full `u32` count indices. Submission admits public metadata, security configuration and exact ordinal/span, reopens a length/SHA-pinned leaf file and freshly verifies the real recursive equation before publishing readiness. Workers preserve exact pair/quartet/odd-count topology, common seal and challenge order, reusable authenticated setup, bounded budgets, publication after fresh parent verification, and joined finish/abort teardown. Normalized public frames and native policies remain alive until workers join.

The detached receiver admits every leaf policy before consuming proof files, checks independent parent/outer setup and outer file pins, then uses the shared exact receiver to prove all child exports through the genuine outer equation. JSON/hash pins alone cannot select a native protocol, key, count or closure. Complete block authority still requires a capacity-aware Global fresh-hook collector and all global providers; those defaults are unchanged.

They check frame 3/7 same-key normalization with changed public counts, distinct claim frames, rejected empty proof bytes, early fresh-claim/security/census rejection, preservation of default public policy/output types, and canonical manifest outer/SHA/config/instance negatives before proof-file consumption. No proof files, worker or guest are created. `src/frontends/riscv/block_v5_native_capacity_exact_codegen.zig` exports `stwo_capacity_exact_body_gate` and retains actual default/capacity Stream start/submit/finish/abort, exact receivers, manifest writes, pinned detached paths and stage teardown without invoking them.
