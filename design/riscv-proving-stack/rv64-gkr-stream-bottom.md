# Opaque streamed-bottom GKR prototype

The opt-in source route removes dense bottom numerator/denominator planes from checkpoint construction and the last two GKR stages. It is selected only by `STWO_ZIG_GKR_STREAM_BOTTOM=1` together with `STWO_ZIG_GKR_TREE_CHECKPOINTS=2`. Dense and ordinary checkpoint defaults remain unchanged. This changes operational storage and replay work, never proof fields, transcript, relation classification, receiver, or security profile.

The numerical core accepts an opaque immutable `MultiplicitiesSource` with a variable count and joined raw-range callback. The callback writes at most 64 requested M31 numerator and secure denominator values from the caller's durable source. The frontend adapter maps these physical fact spans to the original NativeProvider and RowSink authority, using one 128-lane row scratch area and exact 0/1 padding. It never reconstructs expanded MAIN columns or stores a full raw plane. Metadata and challenges remain immutable until all joined work returns; no source pointer escapes in the resulting proof or artifact.

The first even checkpoint is constructed from bounded raw tiles using the original adjacent fraction reductions. Missing odd levels use the qualified lazy checkpoint implementation. The final virtual and raw bottom stages replay bounded tiles for the original range sum evaluator and fold kernel. Raw numerator arithmetic stays in M31 until its first fold. That fold allocates only its half-sized secure outputs; subsequent rounds use the ordinary owned oracle. Constant masks read just their required values. No hidden pool, full-size replay buffer, expanded witness, or global cache is introduced.

All callback errors are collected per scheduler ordinal and inspected after the joined wave; output owners unwind before the borrowed source retires. The explicit `cloneOwned` interface materializes an independent owned raw layer because cloning an opaque borrower cannot otherwise preserve ownership semantics. The production source path uses owned sumcheck and never calls this clone path. Its full-raw-plane metric is zero; bounded raw tile scratch still exists and is not represented as a retained heap plane.

The old checked 104-byte-per-fact admission reserve remains conservative and unchanged, including its planned raw-input reserve. Actual materialized raw-plane bytes and planned input reserve are reported separately. A smaller source-specific bound requires a separate phase proof, capacity-aware tests and review. No admission discount is inferred merely from the new API.

Qualification covers Q/OM exact proof/artifact/next-draw parity against frozen original source, fresh terminal MLE verification, mixed heights and tiny constant masks, signed/padded values, zero-pole propagation, callback shape and failure paths, owned clone independence, pooled and held-lease paths, and exhaustive allocation failure cleanup. The frontend range tests compare original dense inputs at row/padded-lane boundaries for widths through 128. Complete two-CPU plus Keccak, ADD and DOUBLE physical proofs freshly close all global obligations in Safe and Fast. Real CPU0 memory/time and source-bound gates are recorded separately; this prototype does not establish whole-protocol 128-bit security or GPU qualification.

Real CPU0 uses four same-binary alternating ABBA runs, toggling only the streamed-bottom flag with checkpoint2, q70/P26/fold4, sixteen workers, and the unchanged tight 104-byte admission. All sixteen authoritative artifact hashes match and all four independent fresh receivers accept. Numerical requested-owner peak falls from 7,233,043,898 to 2,691,389,018 bytes (62.79% lower). Full raw planes fall from 4,541,656,320 bytes to zero, while the old planned input reservation remains 4,541,656,320 bytes. Maximum RSS is 13,826,523,136 versus 11,047,092,224 bytes; it includes the rest of the prover.

Median proving time is 8.9322 to 9.2271 seconds, with total GKR time 2.6928 to 2.9150 seconds. Raw projection moves from the old input phase into the numerical phase, so numerical time alone is not an equivalent stage comparison. This is an observed modest CPU replay cost for a substantial owned-memory reduction, not a whole-block or GPU performance claim. The remaining requested peak closely matches the retained even-level bank (~64/3 bytes per fact); staggered sumcheck dimensions avoid materializing every instance's first folded half simultaneously. Original backing-capacity admission still needs its separate conservative phase proof.
