# Two LS instances inside one CPU commitment

The opt-in `Geometry.ls_tail_log` adds a second ordinary load/store component to the existing CPU PCS. It adds no wrapped proof, CPU execution pass, RAM initialization, epoch or clock namespace. The CLI selects it with `--ls-ladder=20,18`; defaults keep one LS instance.

For total `T`, the canonical split is `head=min(T,2^ls_log-1)`, `tail=T-head`. An enabled tail must have `0<tail<2^tail_log`; an absent tail requires `tail=0`. Both present instances retain one inactive terminal row. Native events are sliced once, without rebasing their absolute CPU ticks, and each existing native formatter writes its own final MAIN directly. No larger LS witness is built and compressed.

Role `ls_tail` is appended at ordinal17, preserving previous role ordinals. Its widths are the same LS96 authority, fixed3/MAIN79/INTER96. Absence has zero widths and no component, fixed allocation or witness. The immutable key depends on program and role geometry, never event counts or boundary contents. A test reuses the same key with 65 and66 authenticated events.

Both instances share RAM14, OWNER19, U16, U8 and selection challenges. Histograms include every physical row, including padding, and both are merged before the shared table constructors. A private merged selection histogram outlives MAIN retirement. INIT and TERM cover the union once. The existing five LS ledger fields remain: RAM is separately constrained, and the existing LS96 local combined prefix authenticates the non-RAM aggregate.

The core ledger appends five tail fields after the previous32+selection fields. `P.CLAIM_COUNT` is38; wrappers derive their extensions instead of duplicating33/38/43 constants. `P.ramClaim` includes head, tail, INIT and TERM, so only actual RAM debt is exempted by global/service local closures. An absent tail must supply five canonical zeros; a balanced ghost claim cannot cancel another debt. Components derive their active counts from the trusted total and immutable capacities. OWNER includes the CPU epoch/tick, so duplicate or missing events cannot be hidden by moving requests between instances. Read canonicality still requires the complete REG, FUNCTION, OWNER, RAM and range closures and canonical initialization; a standalone open LS fragment establishes none of that execution authority.

Canonical core schema3 and standalone durable Bundle schema3 replace schema2. Previous proof bytes are intentionally not compatible. Global and service containers retain their format tags, but bind the new core transcript, physical shape logs and canonical claim count. There is no new semantic profile enum.

All native/geometry validation precedes borrowed-source writes under the existing source contracts. The joined memory constructor owns its LS buffers; failure destroys any private completed head and preserves caller-owned event inputs. MAIN/INTER handoffs transfer each present allocation once. An extra private allocation outside the physical roster retains its owner flag rather than being leaked.

The qualified slice includes one-PCS native LD/BEQ proofs, false count/span/claim receiver attempts, constructor OOM and owned/borrowed parity, two-shard global RAM, and positive Keccak and secp service joins. The real4,194,303-step genesis packet is independently fresh-verified in both geometries. It is a genesis-prefix result, not a complete block or new aggregate acceptance claim.

For that packet, 1,202,034 ordinary events become 1,048,575 head events plus153,459 tail events. Physical rows fall from2,097,152 to1,310,720, removing786,432 padding rows and139,984,896 committed source cells. The extra component increases decoded OODS samples by187 QM31 values and increases proof bytes. Range dictionaries are shared, but the existing LS generator builds a selection dictionary per instance, an intentional extra setup cost in this first slice. Main/interpolation batches, Merkle openings and small-instance overhead must be charged. Source-cell area is not a wall-time prediction. Exact metrics, contention qualifications and source pins are in `vectors/reports/rv64-word16-execution-20261031/ls-two-instance-v1.json`.
