# Off-owner CPU assignment retirement

Status: **default OFF; eight focused CPU ownership tests, the full producer semantic check and the LLVM driver build pass.** D2 cold/warm requests on both development blocks pass all artifact-byte comparisons and two fresh receivers. M6 compatibility and performance qualification remain pending. No request-time saving or GPU-busy improvement is claimed.

The accepted D2 headline ownership trace contains 0.657228 aggregate host-thread seconds between joined MAIN assignment and MAIN commitment, with no observed GPU or CUDA API work in that interval. The existing source retires the CPU assignment there. This is a retirement/commit-entry envelope, not a measured function duration or a predicted wall-time saving. See the integration branch's `owner-gap-audit` report for the mutually exclusive interval analysis.

`STWO_RV64_OUTER_RETIRE_ASYNC=1` moves the already-joined CPU `Prepared` into one bounded retirement worker while MAIN commitment and subsequent proving proceed. It does not defer a device reader or transfer a GPU lease. The previous backend assignment is restored and ownership detached under the backend mutex; actual destruction happens outside that mutex. Source release joins before destroying owner/request storage. Dispatch, worker duration and final join wait are reported separately so a moved wait cannot be presented as eliminated work.

The ready scheduler withholds one worker per lane from the original total pool budget, then issues an exclusive permit for that dedicated worker. Pool workers plus dedicated workers therefore remain within the original total. Two lanes per device are refused. Other factory routes have no permit and refuse enabled mode. A 1 MiB stack reservation is charged to an identifiable shared host budget before MAIN device work and held until joining. The corresponding pool-helper stack reservation is reduced; this does not introduce an independent memory cap.

The module admits only bounded chains of the known shared budget and recycler adapters terminating in the thread-safe SMP or page allocator. It checks the actual Prepared, schedule and optional run-plan allocators before detaching ownership. An arbitrary allocator behind a synchronized budget is refused. Spawn failure transfers ownership into cleanup and aborts; all success/error paths retain exact-once destruction, exclusive permits and stack charges through join.

Focused tests use byte-identical production shared-budget/recycler implementations through two thin export modules. They check actual cross-thread allocation destruction, immediate source-error cleanup, spawn failure, duplicate ownership, early worker completion with stack/permit retention, unsupported and cyclic ancestry, budget exhaustion and worker-permit refusal. This is CPU ownership evidence only; it does not exercise CUDA or a full Prepared's device-generated witness. The producer semantic check exercises the real Source/Ready hook; its first shadowed-name compile failure was retained and corrected.

Required gates before integration: both development blocks with all native/bundle/tree/node artifacts identical to accepted references; fresh receiver acceptance; bounded host usage and worker accounting; measured dispatch/worker/join spans; and the same node-level ownership profile showing whether the source-bounded gap actually shrinks. Moving cleanup behind a contended allocator lock may still stall later work. No performance claim follows from the prototype or focused tests.
