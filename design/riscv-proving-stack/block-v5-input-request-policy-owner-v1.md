# Independently reconstructed input-request policy ownership

Source candidate only. No compiler, proof, guest, device or segment invocation
was performed by this author. Original Driver/SourcePages/PAGE and the frozen
forest modules are unchanged by this batch.

## Original authority and durable custody

`block_v5_input_request_policy_snapshot_v1.Owner.create` requires out-of-band
Pins for the original ordered capacity-native policy roster, coverage identity,
expected whole-job input root/length and carrier key. It invokes the original
capacity Prepared validation and original typed public normalization; the pins
include original recursive key/schedule and original public input identity.
These pins must be reconstructed from independent job/source admission, never
transported key metadata. The snapshot does not manufacture a verified flag or
capture. Genuine original proof verification is still required in setup.

The snapshot owns regenerated capacity Prepared/log arrays, shapes, public
output words, original schedules, coverage arrays and statement proposals.
One entries/catalog vector is shared across the original native roster. Every
shape input slice aliases the one retained immutable expected job input; that
job survives original caller policy destruction. Original scalar metadata,
full-u64 pin context and distinct capacity protocol are copied exactly. Foreign
Prepared/shape/key/schedule pointers do not survive the successful constructor.

The snapshot uses a bounded SharedHostBudget retaining its caller budget, a
heap-stable owner/control and an arena whose control stays inside that owner.
Partial factories release all allocation and input/parent leases. Reference
ownership is explicit: consuming deinit/retain contracts do not claim that Zig
struct copies are compiler-enforced moves.

## One genuine publish/reconstruct kernel

`block_v5_input_request_policy_owner_v1.ForBackend(Cpu).build` takes the stable
snapshot, exact independent Pins, bounded original file Loader, recursive
profile/resource limits and Action.publish or Action.reconstruct.

It derives exact 1–4 contiguous WM/v2 window ranges from the independent native
census. For each range, it reads bounded original recursive-native files,
runs the unchanged actual typed original verifier, assembles the real WM/v2
verifier/public-compensation/B5PD prefix-fold rows, and derives the original
parent key and schedule. The copied expected schedule and key are owned by the
new stable setup owner. Publish uses these same prepared rows for proving;
reconstruct derives this geometry before decoding a proposed WM proof.

Next it traverses the exact request forest in topological order. Each cohort
fresh-verifies its real WM/prior-node children, constructs the actual existing
request graph/parent rows and independently derives the expected node key and
schedule. One carrier proof is loaded only at the final common ancestor. No
self/future key enters a child capture: during construction, future/self slots
contain private selected-config scaffolding used only for layout, and each
slot is replaced with its true row-derived recipe before any positive receiver
or proof admission for that slot. Earlier child keys are already genuine. This
is not a public constructor for trusting provisional templates.

Both actions use the same admission, row geometry, schedule, resource and fresh
proof checks. Publish writes exclusive synced proof files after fresh acceptance;
reconstruct reads bounded transport-pinned bytes and freshly accepts them under
the independently derived recipe. SHA/length pins supply only file custody.
On failure, publish removes only files created during that invocation. At most
four original/prior captures coexist per cohort. Whole-owner normative checks
occur at construction/session boundaries, not new per-cell callbacks.

The returned `Built{owner,root}` transfers the actual checked final root capture
with its stable original policies. Publisher does not re-run that root verifier
just to return an owning result. `Built.deinit` destroys the capture before its
policy owner. Further durable reads use Owner.readRoot while retaining Owner.
Standalone CPU `reconstruct` runs the original child/row reconstruction kernel;
it never loads an expected key or accepts a setup seal from proof files.

## Exact CPU driver hookup remaining

`block_v5_cpu_owned_input_request_forest_v1` exposes actual publish/reconstruct
selection with Snapshot, independent Pins, original file Loader and admitted
recursive profile/limits. This replaces the previous forest facade's need for
caller-supplied WM/v2/node Specs. It does not change default Driver behavior.

The canonical caller must now supply its independently admitted Coverage and
original native policies/transport files, construct the stable snapshot, and
invoke this selected facade after original job policy admission. Durable
standalone receive must reconstruct that same original policy from independent
expected input/source admission and invoke Action.reconstruct with proposed
file pins. It must keep Built/Owner alive through upper-parent source readers.
The existing original compact/H callback cannot be cast into this route.

All register/program/scoped compensation and complete source/global obligations
remain OPEN; an input-request root alone is not a closed block. The old cutoff
or source flags are not widened. Original B5PD/public admission hash validation
and forest descriptor/supply lookup costs remain in the imported kernels;
there is no successful proof or end-to-end speed/linear-host-cost claim here.
