# Native compiler reuse after bounded parallel cold setup

Status: source review only; no new implementation or speedup qualification.

The cold native factory (`recursion/block_v7_native_fixed_roster_v1.zig`, `Owned.deriveFor`) independently constructs the original composition graph/source map, DEEP graph, FRI graph, arithmetic lowering plan, transcript plan and fixed routing. It discards those graph products after producing fixed rows. The subsequent live path (`block_v7_native_preparation_v1.zig`, `planWithShared`) compiles the same three graphs again and lowers arithmetic again during row emission. Both paths also independently rederive the admitted profile. This is concrete repeated work, but its share of the actual native-window root runtime has not yet been measured.

A finite opaque native compiler capsule can preserve the existing authority boundary. Its only constructor independently derives and owns the selected pin/epoch/roster profile, then compiles the original equations, source map, PCS graphs and arithmetic plan. Cold fixed rows are derived from that object. Live evaluation fills the original source map from a freshly verified capture, checks exact reconstructed public claims, and evaluates fresh values. Graph clones preserve existing ownership; the arithmetic plan can be borrowed only through row emission, as the already qualified caller capsule does. No source proof, witness, transcript challenge, evaluation or success receipt is reusable authority.

The smallest first change is composition plus DEEP/FRI and arithmetic reuse. Existing helpers `compiled_pcs_graph_clone_v1`, `blake3_native_fri.prepareCapturedWithGraph`, and `finishReleasingRowsWithArithmetic` provide those seams. Transcript compilation should follow separately unless the exact native transcript recorder supports the same immutable-plan replay contract as the caller recorder. Shared-epoch and ordinary transcript modes must remain distinct. The capsule should hold an owned canonical profile and compare the independently selected expected metadata without recompiling the same graph merely to validate it. Every selected template, layout mode, original statement, root, epoch entry, physical geometry, config and public claim frame remains bound.

Capsules should be bounded to the active direct batch, counted in the same request budget, and released once both cold and live consumers have completed. Parallel cold construction currently releases each family compiler product after canonical append; retaining products changes the memory/latency tradeoff and therefore needs an explicit cap. A full-job cache would defeat bounded batching. Read-only capsule use is compatible with the existing nonblocking WorkPool cohort lease; mutable namespace rebasing remains confined to newly emitted rows.

Required qualification: original serial versus capsule fixed rows, main rows, public wires, context, independently derived key and exact final proof bytes; access/no-access and q3 native geometry; canonical/opt-in degree layouts; mutated capture/profile/config/source-map negatives; producer teardown; allocation-failure cleanup; and budget rejection while other capsules remain retained. Measure compile, cold fixed emission, fresh capture evaluation and live row emission separately before estimating an end-to-end gain.

## Existing failure does not establish this optimization's benefit

The retained actual-32K root control failed with `MixedDirectResourceLimit` after five cold arithmetic-fusion logs, at 89.08 seconds and 10,866,835,456 bytes process maximum RSS (`vectors/reports/block-v7-real-window-v2-20261030/native-32768-complete-root/qualification.log`). That log lacks the new guard-specific diagnostic, so it does not distinguish cumulative cold rows from later live/join admission. It is not evidence of allocator exhaustion and does not prove that duplicate live compilation occurred. The newly added diagnostics and composed immutable run must establish the actual guard. Parallel cold compilation changes scheduling, not the resulting rows, while native capsule reuse removes later duplicate construction; neither should be described as fixing a row geometry limit.
