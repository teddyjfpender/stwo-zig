Bounded authority map of the functioning Ethereum native leaf and its native-to-recursive consumers. This is not a whole-repository audit. “One source of truth” means each protocol fact has one defining owner with typed projections; it does not mean one large registry owning execution, AIR, transport, and backend resources.

## Concrete competing active definitions

These are drift risks with live consumers, not demonstrated proof failures.

1. **Base relation schema is repeated.** `opcode_manifest.zig:113` declares 12 relation domains for family policy; `air/lookups/entry.zig:22` declares the same ordered domains and separately defines arities; `air/relation_challenges.zig:67` repeats named arity-bearing fields and hardcoded draw/write order. Typed lookup admission calls `entry.expectedArity` (`air/lookups/opcode_interaction_relations.zig:40` and typed authorities), while native transcript draws through `Relations.draw`; recursive `vm_air_composition_circuit_circuit.zig:703` projects graph relations separately. Consolidate ordinal/name/arity/draw-index facts in a small pointer-free relation schema, deriving native/recording projections and family-domain aliases. Preserve existing numeric values and draw bytes; do not merge concrete scalar implementations merely because the schema is shared.
2. **Ethereum extension draw mapping is independently spelled twice.** Native `ethereum_transcript.Relations.draw` maps 26 scalars to 13 named Keccak/secp relations. Recursive `ethereum_composition_relations_v2.RelationsV2.init` separately maps 13 pairs in the same order; `ethereum_vm_composition_program_v2.zig:325` uses this compiler on the active recursive route. Derive both from one extension relation order/arity schema. Different concrete native/graph relation values are legitimate; separately authored index lists are not necessary.
3. **Infrastructure width/placement projection has two walks.** `air/statement.zig:50,94` defines interaction/preprocessed widths and table-kind conversions, used by statement totals and transcript/layout admission. `prover/base_component_assembly.zig:76` separately maps the same kinds to geometry and adapter identity, used by both native sides; `statement_geometry.zig` separately chooses sharding/row counts. Consolidate immutable widths/kind mappings into a low-level descriptor projection, leaving statement-dependent row counts/sharding and actual object construction in their existing owners. Profile-specific Poseidon widths must remain explicit. Avoid making `air/statement` import the prover workspace to reuse the assembly function.
4. **Keccak mask projection remains repeated in active consumers.** The row-order overlap has now been removed: `air/guest_precompile/keccakf_row.zig` owns the direct→lookup→LogUp sequence for native point/domain and recursive recording. Window-to-sample projection remains consumer-specific and is the next shared-layout seam when optimizing the measured evaluator. See `keccak-authority.md`.

A smaller cleanup candidate is duplicated pinned semantic constants: `opcode_manifest.semantic_authority_revision` repeats `isa/authority.sail_revision`; Keccak execution digest appears in both `isa/execution_profile.zig` and `keccakf_authority.zig`. These should be aliases or share a dependency-safe leaf constant owner when touched. Existing digest/vector tests remain valuable independent evidence; do not erase them while removing the duplicated runtime value.

## What is not competing authority

- Architectural `isa.decode.Opcode` includes ECALL/EBREAK and differs intentionally from wire-stable proof opcode IDs. The explicit checked mapping is necessary; enum unification would risk host-control admission and protocol identities.
- `runner/decode.zig` and `air/program/opcode.zig` reexports contain no second decoder/ID definition. Import-path cleanup can be mechanical after consumers move; it is not a semantic fix.
- `runner/execute.zig` is a fail-closed compatibility boundary; imported `*_legacy_test_oracle` modules and Sail/Spike differential tests must not be mistaken for active alternatives. Keep independent reference tests.
- Native arithmetic, recording scalars, CPU/SIMD/Metal kernels, and point/domain sampling are different implementations of shared formulas. Backend memory and scheduling are backend/engine concerns, not new frontend authority.
- Ordinary/Initial38, legacy transport versions, and non-production provider-omission/adaptive-Keccak profiles have different admitted contracts. Similar filenames do not justify deletion or silently changing readers.
- No additional competing continuation equation was established here: active node-public parent construction calls `SpanStatement.fold`. Its host check still does not replace AIR/proof authentication.

## Consolidation order and proof criteria

The Keccak row-order consolidation now passes scalar, recording/compiler mutation and full serialized proof gates. The measured optimization must consume this shared evaluator and remove only its replaced execution loops; SIMD/lane parity remains future work. Then consolidate relation schema/draw projections as one bounded native+recording change with exact transcript/claim equality, retained negative cases, and independent root verification. Move infrastructure geometry only when an active consumer needs that seam, proving exact column/mask/claim order before deleting old switches. Each change must preserve the 16-case CPU/Metal CSP protocol and worker policy. Keep RV64 a separate future frontend/profile; none of this requires widening shared RV32 values.
