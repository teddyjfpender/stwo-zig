# Complete ROM table recursive verifier, version 1

This source candidate provides a genuine recursive verifier for
`block_v5_program_table_proof_v1`, leaving its provider claim open until global
requester closure. It does not activate a CLI/default, replace mandatory
all-family detached verification or establish a complete recursive block
result. The implementing agent performed source edits and formatting only;
qualification, proof execution and performance measurements remain separate.

`Prepared.init` borrows the independently supplied complete ROM plan, exact
integer multiplicities and B5SS roster. It validates the full ELF program root,
plan digest and fetch census, family `program` index zero, first roots and
security configuration before allocating its fixed/main/interaction log arrays.
Its `seal` is exactly the program sub-seal derived from B5SS. The source-keyed
template authenticates physical log size and compiler geometry. Mutable proof
bytes cannot choose the plan, roots, key or public schedule.

The original owned verifier and the new borrowed capture share one implementation
of the existing checks. Both recompute the fixed commitment from the complete
ROM and admitted counters, check the empty main tree and exact first roots, and
run the real typed AIR/PCS verifier. Borrowed capture owns independent capture
storage under its explicit byte cap and retains no received proof allocation.
Its mutation seal is a consistency guard, not cryptographic acceptance.

The recursive composition records the authenticated public-program compiler
and shared framework LogUp algebra. It constrains the public claim's exact mean
normalization, component mask ordering, coset quotient, coefficient order and
the original composition geometry override (degree-bound delta one, split two).
DEEP masks derive from that same native handle. Existing symbolic FRI, query,
Merkle, opening, BLAKE3 and proof-of-work cohorts constrain the rest of the actual
captured verifier material. There is no host-receipt equality or scalar claim
sentinel in place of those equations.

The native protocol uses two independent channels. Universal challenges come
from the B5SS shared channel; PCS starts afresh from the program proof channel.
The additive version-one `restart` operation authenticates that boundary through
fixed routing to the canonical initial digest and zero draw-counter providers.
It preserves prior challenge exports and PCS root indices. The second channel
replays the original tag, version, source/native-roster/plan/program digests,
first roots and secure claim encoding exactly. Existing transcripts without a
restart retain their previous operations, framing and schedules.

`Bus.Values.fromTable` reconstructs public values from independently admitted
plan/seal/roots plus the expected open claim. Its wire providers close both
occurrences of the B5SS seal, all other public transcript roots, first-root
absorption and Merkle reads, canonical claim bytes and the actual claim graph
input. Repeated public root reads accumulate their exact use counts. The
parent protocol also binds index, log size and fetch census in the public
statement; the census is authenticated by the complete independently validated
plan and fixed commitment.

`Stage.ForBackend(B).publish` obtains a real capture, constructs the entire
verifier row set, proves it under the distinct reusable protocol, encodes it and
freshly verifies it before sink ownership transfer. Its optional typed
`SetupCache` uses the shared bounded `ForModules(B, Bus, Protocol)` worker cache;
both cached and cold paths consume one-shot rows and bind current public values.
`Leaf.verify` accepts independently pinned key/schedule/policy and performs
strict decode plus genuine recursive verification. Its open result still needs
the global native request relation to close.

The source-only fixture root is
`src/frontends/riscv/block_v5_program_table_recursive_test_root.zig`, filter
`ROM recursion:`. Seven named tests cover native compiler OODS versus symbolic
parity and mutations, exhaustive construction OOM, independent ROM/census
admission, exact two-channel framing, prefix OOM, public statement/security
binding and repeated restart routing/counters/exports/version rejection. Literal
metadata is used only for admission tests, never as an accepted proof capture.
The separate object root
`src/frontends/riscv/block_v5_program_table_recursive_codegen.zig` retains real
borrowed verification, all preparation cohorts, cached/cold publication and
fresh receipt bodies without invoking them. Candidate source pins and safe
qualification commands are recorded in
`native-program-table-recursion-source-candidate-v1.json` under the campaign's
`cpu-performance-gates-v1` directory.

Global recursive provider cancellation and completeness, remaining provider
families, durable transport integration and canonical orchestration remain
separate engineering and qualification steps. No hardware, STARK or timing
result is claimed by this source candidate.
