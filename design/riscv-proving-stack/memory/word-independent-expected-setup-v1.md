# Independent native memory expected setup

The CPU supplemental receiver and durable RAM/range forest now reconstruct
native leaf expected keys from the original independently admitted policy.
Neither a native proof, verifier capture, producer callback, received key nor
received fixed rows is an input to this expected-key factory.

`providerPolicyForBackend` builds the original native graphs, fixed transcript,
PCS paths/openings, public/private suppliers and complete compact fixed roster.
It uses the one original fixed-key commitment body and converts that geometry
through the original family protocol. The fixed owner is released before the
factory returns; only the key and owned public routing schedule survive.

The default receiver and memory forest retain one bounded expected setup entry
per current family. Its fingerprint binds the original native ABI/template,
full configuration, profile, row log, transcript retry capacity and preparation
budget. Hits validate the current original source admission and authenticate
the cached key identity, context child/config and schedule digest. A miss evicts
before reconstruction. Cache metadata is charged to a retaining aggregate host
budget; fixed construction uses the separately bounded caller scratch budget.
There is no persisted cache format or entry injection API.

Every original base proof still undergoes fresh verification. The supplemental
receiver releases its original proof and capture before loading the recursive
proof. Forest publication needs that genuine capture once to construct the
actual recursive witness; reconstruction releases it after original verification
and receipt collection, before reading the staged recursive proof. Cheap live context,
row-log and exact schedule parity precedes producer admission. The original
producer commits the live fixed columns and admits the independent expected
root, while reconstruction freshly verifies the recursive proof against that
same independently derived root. Metadata parity alone grants no authority.

The production change avoids rebuilding a private recursive witness merely to
derive an expected key during supplemental receive. Identical independently
admitted native templates reuse key/schedule setup across leaves. Native base
verification, recursive proof generation and independent final verification
remain. The memory forest also derives its ordered node specs from the independent
V19 compact fixed catalogue before processing any node proofs. Each selected
spec and its direct node children are authenticated against the catalogue
inventory. Reconstruction verifies the staged node against that expected spec
without loading child captures or constructing a private recursive witness.
Publication checks the original partitioned row logs and context before the
original producer admits the live fixed commitment against the expected root.
No end-to-end time or peak-memory improvement is claimed without an
isolated measurement.

Focused qualification consists of fingerprint separation, cache metadata
lifetime/resource guards, independent key/context/log/schedule mutation guards
and the existing publication and durable memory-catalogue regressions. The
root retains the actual cache factory and both full production integration
bodies without invoking a commitment, segment, STARK or device operation.
Real cold/hit key commitment parity and positive end-to-end proof acceptance
remain runtime obligations. V19 default node integration is authored but awaits
cohesive body qualification. Other provider expected factories, the PAGE/memory
join and complete global block root have separate independent-setup work.
