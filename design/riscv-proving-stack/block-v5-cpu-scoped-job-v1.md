# CPU scoped-job integration v1 — source candidate, OPEN

This batch connects the actual capacity CPU driver to the existing eight-family
heterogeneous scoped kernel. It is an explicit supplemental option, not a
complete-block receipt or a change to canonical q70/pow26 defaults. No compiler,
proof, segment, guest or device run was performed by this agent.

`Driver.Options.scoped_job` requires `recursive_families`. The real call to
`ScopedJob.publish` follows native leaf queue and family joins, original
`Detached.verify`, and `RecursiveReceive.verify`'s original-proof expected-key
reconstruction. Assembly, native Prepared, stable caller catalog, original source
owner and all store schedules remain live until the callback returns. Existing
Global.VerifiedGlobals and default legacy/capacity behavior are preserved.

`Sources.create` derives Coverage from independently admitted
`Assembly.global_pins`. It admits exactly the real native leaf files, sparse
native-fused selection, sparse caller arithmetic/fused pair, actual lane/range
providers, ROM and six-table lookup groups. Typed absence creates no file or
zero-span provider. Original codec metadata supplies proposed claims only.
Source masks, frames, roots, recipe, ordinal and claim arrays are checked by the
original typed normalization and pairing policy; no selected artifact key is
admission authority. The initial all-job original source frame set is retained
once, subject to the cell and metadata limits.

`Fold.run` keeps at most four fresh original/lower-parent captures per node.
Companion and field-safe provider cohorts use the existing normative planner,
including exact carried tails, not power-of-two padding. It reloads original
proof bytes from the real stores, checks their actual original leaf verifier,
derives original verifier plus merge rows, binds the original B5ZC context to
job/coverage/source/recipe, derives the exact expected key and schedule, produces
the real parent and invokes its real fresh receiver before publication. The same
scoped equations and public supply prove all forwarded slot bytes and all exact
local source uses. Proposed output sums do not replace these equations.

`Setup.prepareJob` clones and normalizes the independent full policy and derives
Scoped/Cohorts/Routes once. `finish` consumes this stable setup on success **or
failure**, runs the original Owner's node/key/schedule/source admission and
transfers that same allocation; it does not reconstruct another whole-job setup.
The old `init` delegates through the same two kernels. Immutable Prepared owners
remain borrowed. `bindIndependentContext` forwards the exact existing B5ZC
kernel. No serialized token or caller boolean skips validation.

The real standalone `Receive.verify` reconstructs expected leaf templates from
original durable base proof bytes, including actual native captures. Each caller
arithmetic/fused pair remains live together and every original Store.take is
consumed once. It compares all inventory key proposals with independently
rederived templates, reconstructs the source roster once, derives node geometry
from freshly verified children and verifies proposed parent bytes before the
same setup transfer. The original base reader and independently reconstructed
source owners must outlive the returned Received owner. Teardown runs folded
Owner, source owner, then bounded transport/session owners. Original proof
buffers are destroyed with the base Store allocator; capture/row scratch uses
its own phase budget. This standalone API is source-engineered and unqualified;
it does not claim a complete source receiver from independently expected SHA.

Both `B5RLOP01` and new `B5SCJOB1` inventories contain transport/key proposals.
Their hashes grant no proof authority. Node raw files use the real existing
scoped proof grammar; detached expected keys come from original rows, not header
self-hashes. `sourceFilePins` is an additive bound-pin snapshot in writer **or
reader** mode. Original writer-only filePins, actual fresh loaders, consumed
states and bytes remain unchanged; snapshots never mark a file verified.

The normative owner phase and node metadata are independently capped; per-node
proof/capture/row phase has a separate bound under the aggregate driver budget.
Only node schedules, proposed outputs, normalized compact sources and file pins
persist across folds. Node proof blobs, constructor captures, native replay and
PCS owners do not persist. Source cells, parent count, each proof, total parent
bytes and manifest extent have explicit checked bounds. Existing raw
Bus.Values/Rows validation still rescans global normative routing during this
first late-bound geometry pass; that cost has **not** been eliminated. The
finished immutable Owner retains the qualified local admission path for later
reuse. No runtime speedup is claimed.

The existing H/compact native ingress remains limited to cycles below 2^30 and
its original frame caps. This path rejects larger clocks instead of truncating
or coercing Exact's genuine full-u64 B5WM sources into H. The current 139M-cycle
stopped workload fits the clock bound, which says nothing about the total proof
resource admission. B5WM selected ranges (fan-in <=4), lazy original selectors,
compensation exports and shared-input tail carrier require a distinct typed
higher source and same-parent graph. They are not yet consumed by this callback.
Its input-root relation is currently explicitly unavailable. Place a future
proved tail carrier once at the exact common ancestor with exact consumer uses;
do not reverify its full proof per window cohort.

Program/register public compensation, terminal boundary, initial/final/first-
touch/input source authorities and full final residual remain integration
obligations. Native-fused source binding retains the independently pinned
proposed native link; only real native/fused child proofs and scoped pairing
constrain its exports. Neither manifest presence nor the new Report creates a
ClosedBlock. The future compensation/provider/source graph must join the same
actual lower proof byte sources under its distinct protocol and independently
reconstructed policy. No RAM filtering/default activation occurs here.

The authored nonproving checks cover exact eight-family nonrounded coverage,
sparse companion/typed absence, stale census/source requirements, original
coverage allocation failures, canonical LE output decoding, B5ZC forwarding
parity, setup consumption/resource guards, legacy wide-clock rejection and
reader pin snapshot/ownership failures. A marker retains actual dual Driver,
source, original verifier, node publisher/fresh reconstruction and init/transfer
bodies without calling them. Full positive JobSetup finish/OOM parity over a
real independently admitted full heterogeneous fixture remains stronger runtime
coverage to add; current tests do not claim that positive factory execution.
