# Ready recursion with per-device FIXED setup: isolated candidate

Status: default off; host qualified only. This candidate has not proved a two-GPU request and must not be promoted on the strength of the existing serial-device-FIXED or ready-CPU-FIXED receipts.

The explicit `recursion_device_fixed_candidate: true` option can accompany `recursion_mode: "ready_candidate"`. Each physical lane already owns a separate native context, Outer controller, helper pool and factory. The new selection calls that lane's existing `factoryWithDeviceFixed()` rather than its CPU-FIXED trace-only factory. It changes no field arithmetic, proof profile, transcript, receiver authority or output framing. No CUDA source or runtime image changes are required.

Admission still requires combined proving and a strict independent recursive receiver. Serial mode retains its one-GPU restriction. Ready mode retains distinct physical contexts, the total worker limit, pending-authority limit, host-budget ownership and charged helper/coordinator stacks. Existing native device caps and immutable-cache caps remain enforced. Concurrent device-FIXED work can increase measured per-device memory pressure; the old serial memory observations do not establish fit for this combination.

The authored manifest remains pinned into both the ready and device-FIXED manifest copies. Existing harness checks require their hashes, physical lane and worker accounting, and an actual device-FIXED preprocessing marker for every fresh recursive node. Combined reporting derives the backend from the installed factories. Mixed CPU/device-FIXED lanes are rejected before production rather than reported as a uniform device backend.

Host checks cover explicit/default admission, 1/2/4-device plan propagation, strict receiver and worker/pending rejection, missing node markers, wrong backend reporting, real combined factory selection and mixed-backend rejection. Production combined semantic checking forces the new constructor through type analysis. These are source and orchestration checks, not GPU correctness or performance measurements.

Required physical gate: one explicit two-GPU request using the same native guest, input, policy, host budget and per-device caps as the CPU-FIXED ready control; record all factories' backend markers, both manifest-copy hashes, actual lane/device/worker counts, request-lease cleanup and physical peaks. Require exact native/outer/root/tree bytes plus independent CPU receiver acceptance. Then compare timings with the ready CPU-FIXED control, recording contention and cold/warm status. Until that passes the option remains off and this isolated branch is not a production merge recommendation.
