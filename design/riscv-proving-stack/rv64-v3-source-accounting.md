# V3 source-derived lookup accounting

`rv64-source-derived-services-v3-lookup/v1` identifies the receiver-derived source accountant in `services/gkr_local/source_bounds.zig`. It is a reporting identity, not a new proof, fixed-key or Fiat–Shamir identity. Each CPU scope records its actual `namespace_count`:9 for the original mode and10 when receiver-admitted `cpu_u8_pairs` selects the byte-pair CPU/AND-table path. The geometry, physical MAIN, child instance roster and distinct V3 draw tag already authenticate that mode. No transcript bytes change here.

Candidate production preflight uses this source-derived accountant on both produce and fresh verification, and repeats it when constructing the independent execution inventory. It counts the complete `fractions.Relation` catalog, using the paired emitter cardinalities for paired geometry. New V3 BYTE provider support/poles, full physical Wire slots, sponge RAM/KIO and D64 RAM are included. Weighted JUMPDEST table uses are separated from ordinary signed OWNER mass: unit table consumers must remain below the characteristic and valid support must be exactly8448; all physical OWNER denominator slots remain in collision/pole accounting. A local fact proof does not replace global RAM/KIO/Wire closure.

The older `om31_security_candidate.ledger(Facts)` remains a nine-namespace diagnostic envelope with its existing identity. It is used by legacy policy unit tests, not live V3 lookup admission. Reinterpreting that ledger or its old identity as the V3 budget is invalid. Live `SourceBounds.derive` constructs the actual conditional lookup-degree ledger and enforces `requireLookupOnlyBits(128)`; it does not consume producer-supplied Facts. Reporting the new profile together with per-scope namespace counts makes the distinction explicit while preserving old proof/control bytes.

This slice also rejects a sponge request/log-presence mismatch inside source preflight itself, in either direction. Previously full execution acceptance already rejected it through `protocol.admitSponge`; the change closes an inconsistent standalone diagnostic report, rather than repairing an execution acceptance bypass.

The source-derived check covers lookup-root-count terms only. `security_qualified`, `transcript_round_bound_qualified` and the whole-protocol certificate remain false. GKR, composition/OODS/DEEP/FRI, adaptive multi-scope Fiat–Shamir/hash work and outer recursion still need the documented composed analysis. The pinned30-proof numerical result is not automatically the bound for a new V3 block roster.
