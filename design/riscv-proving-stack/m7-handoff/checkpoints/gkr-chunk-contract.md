The current partial frontier is an optimization, not the requested chunk-bounded implementation. It omits only the largest product level, fuses two ingress levels, retains smaller checkpoints, then reconstructs the omitted level once after those checkpoints have closed. Its exact requested workspace for the observed outer class is 15,046,661,376 bytes, compared with 16,573,396,480 retained-tree bytes. Extra product work is N/2 per nontrivial oracle. The current default remains retained_tree. Numerical parity qualification is separate from the host custody gate.

The genuinely bounded path needs a global memory admission decision across GPU, host store and pinned rings. gkr_chunk_contract.zig provides the proposed cost(chunk), range/address and read/write/fold-round contracts. It explicitly reports numerical_implementation_available=false and cannot authorize either existing enqueue using the chunk estimate.

A sumcheck tile has four globally indexed source stripes, two folded output stripes and an Eq stripe. Four fractions per term are required by the existing at-0/at-2 cubic polynomial. A pipeline slot uses at most 416*C bytes for these numerical slabs, plus bounded block-reduction scratch. Two slots at C=2^18 require about 219 MB before small proof-state/metadata, rather than N-sized device trees. Fixed, MAIN, parameters, composition, PCS and every other owner remain separately charged to the global planner.

A joined host store holds product/fold layers with the same consumed-tree reuse schedule as the GPU implementation. Its payload remains 64*sum(N_i-1) bytes; this is a host-memory tradeoff, not erased memory. Pinned rings add 384*C bytes per pipeline slot. The conservative whole-traversal traffic bound is 512*sum(N_i) bytes, covering product storage and geometrically decreasing sumcheck read/write traffic; it excludes original MAIN/parameter ingress and small control records. This is a derived bound, not measured bandwidth or latency. If the host budget rejects the store, the planner must reject this variant or select a separately costed checkpoint/recomputation policy. It must not spill silently to the currently constrained pod disk.

Each product stage reads aligned global child ranges and writes their exact parent range. Each sumcheck round reads all active oracles' tiles, derives Eq from the full global point bits (including the tile prefix), accumulates one global polynomial, and advances the channel once after every tile and oracle joins. A fold tile reads half-split indices i and i+half, writes output index i, and publishes its host-store generation only after the write joins. Small/missing variables retain the existing mixed-height correction. Poles and sticky source verdicts survive every path. Root/mask/record custody remains independent of chunk buffers.

Required kernel seams are productChunk(source address, levels, output address), sumRoundChunk(four global stripes, Eq global offset, round) and foldRoundChunk(left, right, output, device challenge). Source projection needs a first-index/count extension; resetting a source descriptor to a chunk-local count would change padded lanes and is forbidden. Store callbacks carry oracle, product level, fold round, generation and validated global range. A read/write event owns its slot until joined. The host cannot observe or choose challenges between tiles.

Before enabling: compare every root, polynomial, mask, transcript checkpoint and final proof byte with retained traversal across mixed heights and chunk-boundary sizes; test zero poles in every stripe, cross-chunk Eq-bit carries, final short tiles, stale generations, overlapping windows, failed transfers and cancellation; run whole-producer memcheck; then both real development requests with fresh receivers under the global planner. Any host-store failure must poison publication. No chunk runtime, speedup, or completed Ethereum result is claimed by this contract checkpoint.
