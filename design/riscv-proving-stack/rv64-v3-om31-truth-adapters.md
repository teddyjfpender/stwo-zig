# V3 native OM31 truth adapters

The adapters prove the existing SHA256, arith256_mod, seven curve/field, and secp row ADD/DOUBLE equations in the native OM31 PCS. They are independently sized truth proofs, without adding their MAIN width to CPU rows. This slice does not claim complete execution acceptance, a block speedup, or whole-protocol128 security.

`services/gkr_local/truth_v3_worker.zig` exposes `NativeTruthWorker` (alias `TruthWorker`) with the same init/initWithAuthority, seal, complete, spillMain/restoreMain and deinit signatures as the earlier truth worker. `native_recorder` and `scheme` are available to the coordinator. Source ownership moves only after successful init. Complete returns the existing `TruthEncoded` type with exactly one authenticated Wire35 claim. BYTE queries close inside each provider; they do not become manifest cancellation debt. Only the appended manifest kind `delegation` is needed; the statement and immutable key bind exact family/op/profile/span/geometry.

`truth_v3_catalog` exposes immutable geometry from either an admitted truth or `TruthDeclaration`, plus physical BYTE consumer/pole counts,256-value provider support, and Wire denominator slots including padding. Zero-call, oversized or legacy secp declarations are rejected before key allocation. `truth_v3_retention.forTruth` uses the same requested-payload plan as the CPU/older truth coordinator. It separately counts MAIN coefficients/Merkle nodes, copied narrow advice, interaction output and bounded generation scratch. This is not a complete PCS or RSS bound.

The original equation authority is shared: `emit` now calls the original MAIN body followed by extracted `emitInteraction`. Secure readers interpret old four-coordinate group offsets as group ordinals and load the actual extension degree. The QM31 specialization therefore retains its original indices and operation order. All new native truth components use shared role geometry, OODS and pooled domain evaluation with `LOCAL_GKR=false`. The shared domain evaluator now selects2n for degree3 and4n for secp row's degree4; it does not clone FFT kernels or raise worker stacks.

After MAIN adoption, interaction generation reads copied immutable native advice and replays one bounded native row. It publishes the original cumulative BYTE/Wire chains in eight coordinate planes, closes BYTE exactly and subtracts the final Wire total from every Wire group. Every denominator is checked, including zero-weight padding rows. No full MAIN or tuple matrix is rebuilt or retained. The first implementation uses straightforward native replay; its real workload cost still needs measurement.

The report in `vectors/reports/rv64-v3-om31-truth-20261102/` records ReleaseSafe/ReleaseFast qualification and an explicit reproduction script. Regression proofs useβ1/q4/P0/fold1; candidate SHA and both secp row proofs use actualβ2/q256/P0/fold4 and separately acquired receiver fixed authority. All accept in fresh receivers and reject changed Wire claims. Allocation-failure testing covers witness generation/ownership transfer, not the entire STARK lifecycle.

Parent integration must still authenticate the complete ordered manifest, derive every global challenge from all sealed roots, independently admit all CPU/truth declarations and integer lookup masses, and close RAM/KIO/Wire independently across the whole execution. Candidate profile acceptance remains engineering-only and `security_qualified=false`. Guest/GPU work must preserve these obligations and the exact field/transcript/key identities.
