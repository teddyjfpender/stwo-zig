# Typed resident Metal quotient

The production Metal composition hook now recognizes a separate trusted secure-polynomial capability. Word-v4, range16 and canonical two-event RAM Specs export their actual generic Algebra equations through this callback. CPU OODS verification remains the typed Spec evaluator. The canonical lane executable has its own appended kind, 24 fixed/54 main/92 interaction columns, 117 equations and 271 explicit current/previous inputs. Its commitment domain is the actual `row_log`.

Initialize the core Metal runtime using `MetalCommitBackend.initializeRuntime` with an independently pinned authenticated core AOT bundle, then call `MetalCommitBackend.installSecurePolynomialAot(a, image, independent_sha256, programs, limits)`. The caller supplies the trusted six-program roster generated from admitted word/range/lane Specs. Installation authenticates the image and exact program identities, is owner-serialized, and never compiles runtime source. A marked component without matching installation, geometry, committed source or resources fails instead of running the CPU quotient.

The quotient path binds each retained coefficient pointer/log/extent and committed evaluation pointer to the live PCS trace. The Metal boundary additionally resolves its evaluation pointer through that proof's resident tree map. Only page-aligned coefficient spans whose exact lengths are page multiples can be mapped without copying; unsupported ownership/alignment fails closed. A synchronous GPU blit gathers and pads these immutable coefficients, and the existing resident FFT creates the wider composition domain. Typed equations consume the protocol-wide random powers in canonical component/root order, with exact inverse-vanishing cosets. A GPU IFFT then transfers the resident coefficient buffer directly into the existing `SecureColumnByCoords` PCS owner, without host coefficient copying or CPU AIR evaluation. Outstanding outputs retain the runtime resource count and remain charged against the installed aggregate cap until destruction. There are at most sixteen outstanding owners.

The route does not weaken `require_gpu` policy or override it with hybrid mode. It uses bounded explicit no-copy ingress and existing AOT transforms. Caps include mapped coefficient extents, gather/output arenas, invocation metadata, twiddle ingress and an FFT workspace envelope; retained PCS input owners continue to belong to their proof. Unsupported mixed layouts/domains and detailed work-recorder requests fail explicitly. Current word/range/lane proof wrappers each use one component; components sharing an exact layout/domain can share an additive output.
