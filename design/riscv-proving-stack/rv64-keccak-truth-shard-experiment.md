# Smaller Keccak truth shard experiment

`ethereum/plan.zig` now exposes `truthsWithKeccakMaxLog` with a producer-only bound of 16 through 18. The original `truths` entry point stays log18. No receiver, protocol, CPU geometry or production CLI default changes. The optional producer resource `keccak_max_log` is validated in both control and candidate operational schemas and omitted from JSON at its default18. Full-sized shard call counts are even, preserving permutation pairing and the existing global first-ID/call-count coverage relation.

For the actual block's 32,835 calls, the existing two log18 truths become seven log16 truths plus one log15 truth. The source-derived padded permutation rows fall from 524,288 to 491,520 while active rows remain 476,122. Current authority is 1,923 MAIN and 5,336 OM-classic INTER columns per permutation row. The largest MAIN coefficient payload falls from 2,016,448,512 to 504,139,776 bytes; the largest INTER coefficient payload falls from 5,595,791,360 to 1,399,390,208 bytes. These omit PCS transient scratch, immutable setup and allocator caches. They are not GPU-memory or process-RSS claims.

The tradeoff is material: K truths increase from two to eight, and the exact sum of AIR opening-mask samples grows from 27,548 to 110,192. At eight M31 coordinates per OM value this is 881,536 versus 3,526,144 bytes of sampled values before other proof content. More independent leaves and fixed-table openings must be paid by recursion. This is a peak-memory candidate, not a speed or recursion improvement claim. On native CPU, beta2 MAIN tree pruning also means smaller trees can retain more Merkle nodes in aggregate: pruning only starts at lifted log20. `Store.parkingPlan` remains the actual node custody authority.

`TruthSource.init` already slices the global call-ID span across Advice.keccak without copying or mutating the Advice call inventory. It temporarily copies only the shard's 200-byte input states into the existing source constructor. Smaller shards need no new ownership scheme. Their global KIO claims close through the existing ordered manifest and fresh execution receiver. Changing the roster changes the manifest and proof transcripts; cross-roster physical proof bytes are not expected to match.

An opt-in full-block experiment requires producer CLI wiring while preserving the default log18 path, a worker cap of at least 36 (25 CPU, eight K, three secp) instead of the current explicit 32, a regenerated or omitted stage-two execution permutation, resource-plan admission, then a complete fresh receiver with the same independently expected output/endpoint. The general manifest already supports this count. No full-block or GPU qualification has been performed for log16; neither should be inferred from the pure planner tests.

The Safe/Fast planner gate checks bounded option rejection, contiguous exact call spans, per-shard valid declaration geometry, active slot preservation and full-block costs derived directly from `truth_components.Shape`. Machine-readable totals are in `vectors/reports/rv64-keccak-shard-plan-20261102/source-cost.json`.


The CLI integration helper keeps the historical default-log18 parked worker ceiling32 and the no-store ceiling8. Only an explicit smaller shard bound may admit more parked jobs, capped at64. This limit counts proof jobs rather than worker threads; the scheduler retains its separate32-thread limit. The parent integration owns the final producer call-site wiring and should invoke the helper immediately after declarations are planned, before constructing keys. Resource tests cover default omission, round-trip optional16, candidate pass-through17, invalid15, default36 rejection, experimental36/64 acceptance and65 rejection, plus the no-store8 ceiling. Safe/Fast source gates cover this operational schema; an actual experimental full-block proof remains pending.
