# OP pure-P2 complete native inventory

The receiver now constructs an OP-specific complete inventory before sealing a manifest. `protocol.admitForOp` shares the original genesis, CPU adjacency, epoch, public memory, terminal-state and inherited-provider coverage checks. It adds the actual Tower span to instruction and global RAM/Wire masses without clearing the OP profile or passing through an old production entrypoint. `source_bounds.deriveForOp` separately requires exact contiguous CPU and Miller truth coverage and includes every padded local range/OWNER slot and Miller SSA/canonical-write source bound.

`pure_p2_op_inventory.zig` reconstructs each worker's statement from receiver-owned keys, requests and spans, binds immutable OP geometry through its fixed key, and binds the execution to independently expected program, image, genesis and endpoint. A producer cannot choose a free execution digest or declare an acceptance bit. Native acceptance still requires the physical local GKR binding, every PCS proof and the manifest's zero-sum RAM/KIO/Wire closure.

`pure_p2_manifest_wire.zig` preserves all nine canonical Poseidon2 coordinates for roots and local receipts. `pure_p2_op_bundle.zig` frames those stage-one data and all native proof/claim bytes. Its decoder preflights counts, lengths, canonical field coordinates and trailing data before owned allocation. The receiver supplies its complete source inventory independently; the bundle contains no trusted software, image, fixed-key or endpoint declaration. This transport is deliberately distinct from the earlier Blake-based formats.

The focused ReleaseSafe physical gate runs the actual inherited SHA-256, arith256 and bulk-memory session under `ethereum_services_op_v1` in two shards. The second shard reads values written by the first. Two CPU and two truth proofs occupy 3,915,744 bytes. Independent receiver CPU and truth keys accept both the in-memory and durable round-trip bundles. Missing providers, changed expected endpoint, missing claims, changed physical claims, truncation, count mismatch and byte-cap violations fail. The separate Miller fixture qualifies its CPU/OWNER/RAM/Wire path; the small mixed fixture does not contain a Miller call.

This is a complete small execution qualification, not a complete OP block, recursive aggregate or performance result. Heavy-block capture and bounded parked MAIN coordination remain the next native integration gate. Production CLI admission remains closed. The security label remains **128-bit security target under documented assumptions**, with no certified whole-protocol claim.
