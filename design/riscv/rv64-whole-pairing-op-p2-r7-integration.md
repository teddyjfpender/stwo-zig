# Whole-pairing provider → OP/P2/R7 integration map

Status: source review at `102b95fad`, 2026-11-10. This is an integration plan, not new service/profile admission, an execution proof, a security certificate, or a speed claim. No heavy replay/proof was run. Existing R5, R6 and R7 defaults remain unchanged.

## Existing provider and bounded cost

`src/integrations/riscv_cpu/delegations/op_pairing_mac12/README.md` records one four-pair **finite canonical positive** pairing computation. It includes G1 curve checks, four exact G2 subgroup checks, 87 preparation lines per pair, shared Miller computation and a positive residue certificate. The source has 32,533 MAC12 rows, 1,438 canonical hint writers and 1,460 immutable endpoint assertions. Internal SSA accounts for all 814,785 reads/assertions, including zero-coefficient input ports.

| Role | log | FIXED | MAIN | INTER |
|---|---:|---:|---:|---:|
| Frontier/assertions | 11 | 35 | 33 | 16 |
| MAC12 arithmetic | 15 | 40 | 1,106 | 32 |
| Canonical hints | 11 | 3 | 95 | 32 |
| BYTE provider | 8 | 1 | 1 | 16 |
| Total columns | | 79 | 1,235 | 96 |

The exact native total is **39,043,584 cells / 1,410 columns**: 1,388,800 FIXED, 36,503,808 MAIN and 1,150,976 INTER. Six GKR instances contain 17,961,216 padded facts; BYTE and SSA close independently (`op_pairing_mac12/native.zig:112`), so their debts cannot cancel across relations. These are source-derived native quantities, not recursive verifier cells or GPU costs.

The existing target-parameter qualification is OM31/Blake2s PCS with 32-byte roots, B4/q72/P0/fold4. Its single-worker observation was 14.732 s producer excluding qualification-only checking, including 8.251 s local GKR and 2.084 s terminal binding. It is not an OP block measurement. A separately typed P2 transport is being built by the transport workstream; it must mix all nine canonical root words directly. Wrapping/truncating a 36-byte P2 root into a 32-byte digest is not an equivalent interface.

## Make FIXED independent of the request

Current `bn254_pairing/fixture.zig:175` constructs frontier FIXED bytes from `plan.frontierExpected(row, &model.public)`; the first 24 Fq values are request inputs. `fixture.zig:94` physically equates frontier MAIN bytes to those FIXED bytes. Thus the current FIXED root is input-specific even though arithmetic/hint/table schedules are source-owned. Caching that root by program or geometry would be incorrect.

The proposed production architecture is structurally feasible without a padding increase:

1. Move the first 24 initial SSA writers into the canonical Hint95 role. Keep their original initial SSA IDs; do not allocate substitute IDs or lose their source-derived fanout. Hints become **1,462**, still within log 11.
2. Retain the 30 source literals and 1,460 zero/one assertions in the frontier: **1,490** rows, still log 11. Frontier IDs can no longer be inferred from the old contiguous `row < INITIAL` rule (`lowering.zig:109`); use a source-owned table or explicit mapping.
3. The new input hint rows prove canonicality using the existing 95-column writer (`bn254_hint/source.zig:25`): 32 value bytes, 32 distance bytes, Boolean carries, and final carry zero enforce value < p. No host-only canonicality check substitutes for this AIR.
4. Bind those 24 values to authenticated global Wire input tuples with the service call ID; bind the TRUE result similarly. A global I/O role must also bind the service packet to RAM and the CPU OWNER request. Internal SSA remains a distinct relation/domain and must not be repurposed as global Wire.
5. Regenerate source fanout and BYTE multiplicity from the resulting program. The 24 new rows add 1,536 **active** BYTE queries, but the existing padded hint BYTE instance is already log11 × 64; its padded facts and columns do not increase. Removing the old 24 frontier writers and adding their Hint95 writers preserves SSA ownership rather than introducing a second producer.

For that split **alone**, all four role logs and widths remain unchanged, hence native cells, 1,410 columns and six padded GKR-instance sizes remain unchanged. This excludes the necessary new global I/O role, its bindings, CPU bridge, public claims and recursive verifier. Those costs cannot yet be quoted honestly because the packet/output layout and physical global projection are not defined. Canonical hint MAIN is private proof advice; it is not a requirement to send a 960-byte private certificate through the VM packet.

The immutable key must bind source ROM, arithmetic/literal/assertion schedules, ordered role geometry, relation domains and profile. A request binds inputs/output, call ID/span, manifest, MAIN roots and global debt. An independent receiver reconstructs both layers; it never imports a producer key/root. Until this split is physically qualified, any standalone P2→R7 experiment must explicitly retain independently reconstructed **input-specific** FIXED authority.

## Why no recursive source-only cost is reported yet

The generic arithmetic constraint emitter is reusable, but its current terminal-binding inputs are not symbolic. `op_pairing_mac12/projection.zig:14` stores native `Q` weights, beta, SSA wire, eta and target. `evaluate:40` splats them into the generic field as constants. Likewise `bn254_pairing/fixture.zig:43` accepts `WireFor(Q)`, and `byteFraction:71` accepts native Q beta.

A recursive verifier instead derives these values from circuit transcript challenges and the verified child proof. Feeding a producer's native `Pending` values as constants would either change the key per proof or omit the transcript-to-binding constraint. Consequently the existing generic emitter cannot yet produce an honest complete R7 verifier/source census.

The minimal new seam is shared symbolic fraction/binding data: typed secure expressions for beta, SSA coefficients/offset, eta, lane/Eq weights and target; preserve exactly the native tuple order, dummy lanes and masks. Reuse the original arithmetic emitter, source fanout and canonical writer equations. A new Statement then verifies the child, separately closes BYTE/SSA, recomputes the receipt and evaluates each role's binding against those **derived** expressions. Only after this exists can the source-only R7 row/mask/opening/cell cost be measured. Native 39M cells or a CPU-only digest circuit are not substitutes for that measurement.

## Required bounded evidence before admission

First qualify the static-input split: two different valid inputs share the immutable FIXED root, while their independently expected statements/MAIN roots differ; wrong initial IDs/fanout/literals/TRUE, coherent noncanonical input writers and missing/duplicate producers reject physically. Then qualify one full36-byte-root native P2 provider proof and one R7 group proof from an independent key. Retain positive valid-proof cross-policy controls and negative swapped coordinates, EVM Fq2 order, altered receipt/marginals, missing/extra role, balanced cross-relation debt, wrong statement/call/clock/packet output and source-key substitutions. Finally a complete small guest run must close CPU OWNER/RAM/Wire and all other services, followed by a fresh source-only root receiver with the native proof file absent. Only that last gate supports complete execution-root wording. No heavy block rerun is required to develop these gates.
