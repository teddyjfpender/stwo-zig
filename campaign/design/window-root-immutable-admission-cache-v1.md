## Targeted repeated work

`block_v8_window_root_receiver_v1.Tree.deriveAt` independently derives leaf keys and recursively derives every child key before deriving a fold key. The full driver calls `tree.derive` on both children at each reduction step. A balanced N-leaf reduction therefore repeatedly reconstructs descendant keys, roughly O(N log N) derivations, before the final independent receiver makes another O(N) traversal. The factories compile and commit substantial temporary fixed rows.

`block_v8_window_root_profile_v1.Owned.fromCompiled` retains an admission snapshot, a small PCS shape, CPU/snapshot span, MAIN root, fixed root and seals. `block_v5_recursive_parent_shape_v1.Shape` retains logs, column-log vectors, sample layouts and widths, not evaluated fixed trace matrices. Retaining these profiles is a different memory class from retaining proof-preparation rows. The proposed 213-profile memory size has **not been measured**; there is no claim that it fits below 100 MiB.

## New namespace and trust boundary

Source: `src/frontends/riscv/recursion/block_v8_window_root_admission_cache_v1.zig`.

`Frozen.clone(allocator, InputContext, forest, Limits)` owns a complete immutable context. `InputContext` contains actual ELF bytes, actual private-input bytes, and the independent `Full.Trusted` request: ELF/input pins, expected 43-byte output, total cycles and security configuration. `Full.Owned.derive` reconstructs the initial state and ELF terminal policy from owned copies. A caller cannot nominate a full-boundary digest.

Each leaf is encoded and decoded using the existing exact thin-leaf wire schema. The frozen descriptor binds the complete encoded bytes, actual independently checked snapshot IDs and CPUs, ELF/configuration, window and boundary ports. Raw snapshot words are copied, canonical address ordering is checked, their canonical identities are recomputed, and adjacent duplicate snapshots are retained once. Distinct buffers claiming one snapshot identity must agree byte for byte. A same-pointer shortcut applies only while freezing, under the explicit contract that callers do not mutate input buffers concurrently. No borrowed input pointer is dereferenced after `Frozen.clone` returns.

The forest identity binds the ordered root descriptors. A branch descriptor binds its ordered child descriptor identities, child count and MAIN root. An opaque `Node` also binds the entire frozen forest identity. It cannot select a profile merely by an array index. Content-identical frozen contexts may have identical handles; different scopes, roots, configuration, boundary ports or leaf-wire bytes do not.

`Cache.create` has no supplied-key, receipt or derivation-callback input. It visits unique postorder descriptors and invokes only the existing factories:

- native leaf: `Upper.deriveLeaf`;
- mixed leaf: `Mixed.admitMetadata`, then `Profile.Owned.deriveJoin`;
- fold: `Profile.Owned.deriveFold` using already derived child profiles.

`appendFold(children, main_root)` supports later reduction steps once their actual MAIN roots exist. It uses the same branch identity as a frozen branch, validates every child, and validates an existing parent before returning a cache hit. It does not recursively reconstruct descendants. Expected-key derivation alone does not assert that a proof for a MAIN root exists.

The opaque handles expose no raw frozen snapshot or mutation API. `profile(node)` returns a borrowed const profile, not a successful-verification token. The caller must not mutate reachable storage and must synchronize cache operations. Every checkout independently checks the existing admission/shape validity and compares a sealed structural fingerprint of all semantic profile fields, including fields beyond the existing `Profile.identity`: fixed-root alias, wrapper shape aliases, exact prefix frames, public supply terms, child spans, PCS tree layouts and geometry, CPU/snapshot span and MAIN root. A recomputed ordinary profile seal cannot authorize a changed cached admission. This guards accidental or API-level mutation; it does not defend against arbitrary memory corruption in the same address space.

## Opt-in driver integration

`Pipeline.Options.immutable_admission_cache` defaults to false. The experimental path is available through `scripts/v8_full_block_prove.py --immutable-admission-cache`, which sets strict `STWO_B8_BLOCK_IMMUTABLE_ADMISSION_CACHE=1`. Invocation provenance and the benchmark report record the option. Cache node/depth limits are preflighted before proving.

Cached resume initially decodes complete saved window pairs as **unverified candidates**, never completed receipts. After window files exist, it freezes the canonical leaf forest and independent full context, derives each leaf admission once, verifies every proof byte string under that admission, checks exact requested span/CPU/snapshot/boundary ports and calls `requireCapture`. Only then are saved candidates counted in `resumed_windows`. `admission_cache_setup_ns` reports shared freeze/key setup separately from `admission_cache_leaf_verification_ns` and candidate verification accounting.

For a new fold, the driver obtains checked cached child profiles, freshly verifies their saved proof bytes to obtain the captures required by existing `Fold.produce`, and proves that same fold. The additive `Fold.Artifact.main_root` field nominates the actual produced commitment; it grants no verification authority. `appendFold` independently derives the parent admission once from those children, and a fresh proof verification plus `requireCapture` validates the actual fold bytes/root before publication.

Saved folds can also be reused in this opt-in resume path. A complete proof/proving/timing set and matching ordered child indices are required; malformed or incomplete sets fail closed without falling back to proving or overwriting evidence. `deriveUnboundFoldForVerification` independently derives a temporary expected fold admission with placeholder own MAIN root zero. In the existing factory, own MAIN is assigned only by `Profile.fromCompiled` after the key/admission is constructed. The proof is freshly verified under that independent admission, yielding an authenticated MAIN commitment. The temporary profile is destroyed; `appendFold(actual_MAIN)` derives the final cached profile. Expected/public/admission IDs and fixed root must exactly match the temporary admission, and `requireCapture` must succeed. This explicit parity check fails closed if the factory ever changes the own-MAIN dependency. No proof-byte-offset parser, supplied VK or successful-receipt shortcut is used. Saved folds deliberately cost two independent parent admission derivations; avoiding repeated witness/proof work takes priority. `temporary_fold_derivations` reports the extra factory calls separately.

Historical fold proof, proving and timing files remain unchanged. Each resumed fold writes `node-I.resume.json` with its current verification time and prior-proving-excluded marker. The final summary records `resumed_folds`, `resume_fold_verification_ns`, current-invocation `folds_ns` and the existing explicit resume timing scope. Prior proving durations never enter the new invocation’s whole/fold timing.

This removes repeated **descendant admission derivation**, not child proof verification, new-parent witness generation/proving, or its fixed commitment. The existing cold path remains unchanged. No end-to-end speed claim is made. All cached profiles and owned frozen input copies are explicitly destroyed before the final receiving phase.

The final serialized full-root receiver must continue to use a new independently derived `Full.Owned` and uncached `Upper.verifyFull`. It must reconstruct the canonical tree from the published catalog and actual receiving data. No process-local cache, cached profile, proof of earlier successful receiving or producer-nominated VK is a public-verifier input. Resume admission still requires independently decoded metadata, exact requested span and fresh proof verification; a cache hit is not a completed-window receipt.

## Ownership and resource accounting

`Frozen` and `Cache` are opaque reference-counted owners. Cache ownership keeps Frozen alive after the caller releases its handle. Recognized backing host budgets are retained across allocator leases and released only after control allocations. Arena ownership is explicitly transferred during construction; every error path must release the transferred arena and initial boundary snapshot exactly once.

Snapshot copies can add approximately the complete receiving-data size to the live process. This initial API does **not** claim a memory-free freeze of the existing borrowed 2.7 GiB checkpoint catalog. Transfer of an already-owned frozen checkpoint catalog is a separate possible optimization. Statistics distinguish `profile_live_bytes` (current profile-budget live bytes), `retained_profile_peak_bytes` (the maximum live bytes sampled in `add` after each factory and fingerprint validation have released their temporary allocations), and `key_derivation_peak_bytes` (the budget high-water mark, including temporary wide fixed rows and commitments). Frozen raw snapshots, thin wire bytes, ELF/input bytes and the independently reconstructed initial snapshot are reported separately. The retained-profile peak is sampled at successful insertions; it is not the temporary key-derivation peak. Allocator overhead and control arrays are not labeled as snapshot payload.

Limits bound tree depth, tree visits, unique nodes, raw snapshot count/words/payload, thin-wire bytes/items, temporary key-compilation live bytes and retained-profile live bytes. The cache refuses overflow rather than evicting entries or silently changing statements. Duplicate parent hits remain possible at the exact unique-node limit.
