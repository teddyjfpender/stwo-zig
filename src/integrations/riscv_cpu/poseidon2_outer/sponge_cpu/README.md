# Detached-sponge CPU flavor (closed)

This namespace replaces the CPU's old sponge call/permutation bridge tables with
an eight-MAIN-column frontier. It uses a new typed source roster and local GKR
transcript (`OPSPCPU1`); it never labels frontier equations as an old Frame origin.
The independently admitted CPU setup must have no sponge bridge logs. All other
legacy instances, offsets, emitters and relation challenges remain genuine.

The frontier consumes the complete existing OWNER19 call with Boolean unit
weight. Its pointer limbs inherit canonicality from that CPU authority; its two
clock limbs issue U16/U8 unit queries including padded rows. Epoch is exactly
CPU ordinal + 1. Its global Wire35 tuple contains the fixed namespace, ordinal,
all 19 OWNER coordinates and 14 zeroes, matching the detached descriptor.

`Source.initCalls` checks exact per-CPU call count/epoch/strict clock order before
allocating MAIN. MAIN can be transferred while compact call records remain for
GKR. Range admission preflights both complete histograms before changing either
existing provider. `Frame.Roster.init` physically excludes old sponge instances
and appends a separately tagged frontier. Native source GKR reuses the common
checkpoint prover, bounded payload codec and exact local closure implementation.

The focused test runs the actual OP executor on the existing two-CPU sponge
fixture (fresh hash, cross-CPU message reuse, continuation absorb). Both real
CPU/source rosters close their full local GKR debt with the replacement OWNER
consumer; changed call coverage and epoch reject. The legacy artifact prefix is
only a borrowed view of that verified common-point artifact, never a fake proof.

The complete physical native join is now qualified: two real OP CPU shards,
three sponge calls/five permutations and the original six-call Keccak truth

keys accept all four proofs; physical source binding and RAM/KIO/Wire close.

## Pending-fragment API and production handoff

`Worker.init` borrows an independently derived CPU/setup key and takes the actual
legacy source + frontier on success. `seal` transfers their existing MAIN
allocations once; narrow metadata survives. `complete(manifest)` reuses original
classic global witnesses, the legacy binding/component set and the accepting
PCS, then appends the one typed frontier. `verify` rebuilds the new local roster
and binds original legacy instance marginals through a borrowed prefix of the
verified common-point artifact. It independently checks public RAM boundary
claims before authenticating the physical proof. It returns pending global
claims, never execution acceptance.

The detached `sponge_local_gkr/worker.zig` uses the same source equations,
checkpoint GKR, component set and stage helpers as its qualified standalone
control. `pure_p2_truth_worker.SealedScope` is a narrow pending-fragment seam:
source key/family/statement and sealed MAIN are checked independently; the full
manifest is absorbed before challenges. The existing Pending wrappers retain
all prior authority checks and invoke exactly the same stage body.

General cross-CPU KIO allocation is a required runtime design step. Legacy IDs
interleave direct Keccak and Sponge ranges per CPU; concatenating Sponge records
from arbitrary CPUs need not yield a contiguous ID interval. A new suite must
either allocate all direct ranges then detached ranges with the receiver owning
the exact truth order, or authenticate explicit run/call ID spans. It must not
silently concatenate old ranges under one `first_id`. The current join proves
a contiguous interval2..6 only. OWNER/Wire identity remains original epoch/tick,
and the detached provider, rather than the CPU row, proves permutation chaining.

Production must also derive whole-worker and per-relation integer mass bounds
from the source roster and g.calls/g.permutations, admit exact ordered coverage,
pin the endpoint/image independently, and add the new equations to recursive
source admission. The fixture uses conservative explicit mass bounds and the
existing native genesis/CPU/memory-boundary authority; it does not activate any
existing Suite selector or replace its complete security review.
