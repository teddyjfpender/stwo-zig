## (a) EVM MUL / EXP on a plain 512-bit arith256 service: not built (ceiling too low)

The MUL handler is 64 straight-line instructions: 8 loads, 16 mul/mulhu, the
carry adds, 4 stores, dispatch and checks. Across the 15 blocks MUL makes up
6.10M instructions, or 0.0137 instr/gas (0.43%).

An ideal service call would cost about 27 instructions:

- zero c in the free slot above the stack top;
- point the packet at the operands already in place on the stack;
- ECALL;
- copy lo back.

That saves at most about 37 x 95,310 = 3.5M instructions, -0.25% instr/gas.
In committed cells the service would cost 3,692 cells/call (the arith256_mod
truth plus bridge, measured), against about 37 x 127 = 4,700 CPU cells saved.
That is roughly -0.05% bits/gas. It would also need a fallback when the stack
is full, a new truth AIR and bridge, and recursion support.

EXP is smaller still: 12,828 calls, 0.0028 instr/gas inline.

The existing execution-only candidate `--candidate-set ...,mul`
(`stwo_arith256_lo`: a 20-word packet zeroed plus memcpys) is slower than this
ideal, so it can only show less. The admitted plain arith256 service was
therefore not built: its ceiling is below the noise of the other client steps,
and it would add proof surface with no measurable return.

## (b) Patch 0030: deferred gas test for pure stack opcodes (kept)

Per opcode, `dispatch_cgoto` paid 6 dispatch instructions, 1-2 stack checks
and 2 gas instructions (`addi`, then a branch on the sign).

The patch changes the gas check as follows:

- **Pure opcodes** are those whose implementation has type `void(StackTop)`
  (arithmetic, compare, bitwise, POP, DUPn, SWAPn, PUSH0), plus PUSH1..32.
  Their only effect is on the EVM stack, plus a read of the code for PUSH.
  JUMPDEST is excluded. These opcodes now only subtract their constant cost.
- **Every other opcode** tests `gas < 0` after charging its own cost,
  including the zero-cost STOP, RETURN, REVERT and INVALID.
- **Failures with gas already negative on entry** report EVMC_OUT_OF_GAS. This
  covers the stack checks and the undefined-opcode check (both run before the
  opcode's own charge) and the `TARGET_OP_UNDEFINED` label.

Why this is exact:

- Gas never rises during a run of pure opcodes.
- The first non-pure opcode stops with OOG before it has any effect.
- Every failure on the way gets the status that the per-opcode check would
  have reported at the opcode that ran out.
- An exceptional halt returns gas_left = 0.
- A pure run is finite: it only moves forward, JUMP/JUMPI are checked and the
  code ends in STOP padding.

The switch dispatch (`dispatch<false>`) keeps evmone's per-opcode checks. It is
the reference for the host differential fuzzer, `tests/xlat_difffuzz.cpp`
(fused cgoto vs plain switch). The fuzzer compares status, gas_left, refund,
output and all host effects, and generates tight-gas programs.

The patch also changes PUSH1..7: they now load the immediate before writing
the stack slot. The compiler cannot rule out code/stack aliasing, so
`push({})` followed by the value had stored limb 0 twice.

Measured: 28.1 -> 27.2 instructions per dispatched opcode. Examples: PUSH1
16 -> 14, POP 10 -> 9, DUP2 19 -> 18. MLOAD/MSTORE each gained +1 from the
remapping in their cold paths.

Tests:

- `build.py --host --tests` passes.
- xlat_difffuzz: 20k and 200k programs (800k runs), 0 mismatches.
- Mutation checks, each caught with 5 mismatches within 20k programs:
  - no OOG remap in the failure path;
  - no gas test on zero-cost non-pure opcodes;
  - no remap at `TARGET_OP_UNDEFINED`.

Not kept: building every PUSH word in a local `w[4]` array. LLVM's register
allocator then spilled the stack-bound registers of `dispatch_cgoto`, adding
one stack load per opcode. Scored went 3.283 -> 3.298 (worse).

## (c) secp glue: field and scalar products on the admitted arith256_mod service (kept)

`fe_mul` (mod p) and `sc_mul` (mod n) in `glue/secp256k1_stwo.cpp` were
RV64IM schoolbook products with special-form reductions: 209 and 443
instructions per call. Block 24,628,607 calls them 1,806 and 831 times for its
78 deferred signatures plus the hint checks, about 23 and 11 per signature.

With `ADMITTED_ARITH` (in the default v3 set), both functions now make one
`arith256_mod` ECALL. Each modulus has its own static, 32-byte aligned packet,
with c = 0 and m = p or n written once. The service writes only r, so those
words stay intact.

Why the results are identical: the admitted truth AIR proves
`a*b + c = q*m + r` with `q < 2^512` and `r < m` for any 256-bit inputs
(`design/riscv-proving-stack/rv64-arith256-service.md`). The software
reductions also return the canonical residue for any 256-bit inputs.

Effect on block 24,628,607: arith256_mod calls rise from 319 to 2,956, and
instructions fall from 26,894,760 to 25,837,408.

Test: `build.py --tests` now runs `secp_differential` twice. The second build
uses `-DADMITTED_V3 -DADMITTED_ARITH`, with the host's independent intx
emulation of 0x0003_0021. It compares 3,000 random and edge-case recoveries
against evmone's software recover and runs the deferred-batch accept/reject
checks: 0 mismatches. A mutant that flips bit 0 of some mod-n products is
caught (40 mismatches).

Not pursued: `double_mul`'s remaining 0.09/gas. It is mostly the 12-word copy
of each table point into the ADD packet, which the add ABI (accumulator and
operand adjacent in one packet) requires. Wider windows trade roughly as many
table-build adds as they save.
