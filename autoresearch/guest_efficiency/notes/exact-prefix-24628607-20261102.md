## Newer PR head (807d0b531) cannot prove the block yet

origin/codex/rv64-guest-efficiency moved during this run. The new head makes three CPU layout changes the
default on the v3 route: fused-tail CPU interaction, U8 byte-pair lookups and LS-D64. With binaries rebuilt at
that head, `produce` on this same request fails after 5 s with:

    error: InvalidCombinedRangePhase

The error comes from the precondition in services/roster.zig `mergeAnd`/`merge`: the CPU AND/range tables
must still have their classic shapes before service multiplicities are merged in. It still fails with
`--no-ls-dword`, so the cause is the fused-tail/byte-pair layout meeting the services lane, not LS-D64. Until
this is fixed:

- There are no exact cells for the new default layout.
- The CPU figure above is for the 40-column CPU interaction layout.
