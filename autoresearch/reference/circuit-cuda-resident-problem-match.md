# Circuit recursion CUDA: problem match before optimization

Task and required semantics: Produce the same circuit STARK proof and Fiat–Shamir transcript as the pinned Rust R7 flow, then aggregate PIE proofs through wrap, fold, and root. No proof-stage host reads or CPU fallback; the only download is the terminal proof envelope.

Inputs, scale, and model: The recorded circuit registry has 11 AIR components, four mixed-height trace trees, four-fold FRI, and 70 queries at the canonical configuration. The local `geometry.zig`, `resident_composition.zig`, and `resident_decommit.zig` derive exact tree, source, and opening counts. CUDA time includes launch and transfer costs; GPU memory is a hard feasibility constraint.

Constraints and structure: The transcript order, canonical sample order, plain Blake2s Merkle profile, two distinct PoW challenges, and all four committed trees are fixed. Fixed circuit topology and preprocessed columns can be prepared before proof execution. Witness values, interaction challenges, and openings are proof dependent.

Candidate matches and evidence status:

| Candidate | Relationship | Fit and risk |
| --- | --- | --- |
| Lifetime-aware offline arena packing | Exact allocation subproblem; implemented in `runtime/arena.zig` | Derived from stage lifetimes; aliases only nonoverlapping ranges. Check peak and retained proof bytes. |
| Streaming or recomputation of commitments | Time/space tradeoff, not equivalent without preserving coefficients and authentication paths | Hypothesis for later profiling; adds kernels and risks changing transcript material. |
| Host-assisted proof generation | Different computational model | Rejected: violates resident proof requirement and obscures GPU performance. |

Chosen canonical problem and mapping: Assign each resident buffer a size, alignment, and inclusive stage lifetime. Reuse offsets only for nonoverlapping lifetimes, while the terminal envelope remains live from ingress through publication. This is interval-constrained storage allocation; the existing deterministic arena planner is the implementation boundary. No new allocation algorithm is needed before measured size is known.

Complexity and limits: Planner cost is secondary to proof execution; GPU peak equals the maximum assigned arena extent, plus CUDA runtime reservations. The proof must fit H100/H200 capacity with a safety reserve. The exact crossover of recomputation versus retention is unknown until profiling.

Selected transfer and falsifier: Bind the circuit plans to one proof-owned arena, prime all immutable tables at ingress, execute the entire stage schedule, then decode and independently verify the one downloaded proof. The hypothesis is that this removes intermediate transfers and exposes the real CUDA bottlenecks. A nonzero mid-proof read, CPU fallback, invalid verifier result, or memory above the target GPU falsifies qualification.

Correctness and benchmark plan: Compare stage roots, sampled values, nonces, FRI coefficients, and decoded proof against CPU/Rust vectors; verify a genuine multi-PIE wrap→fold→root proof. Record ingress, each GPU stage, publication, total latency, peak device memory, and proof bytes for all representative PIEs before optimizing kernels. Only optimize measured dominant stages, and repeat byte/parity checks after each change.

Measured qualification (H100 SXM, `sm_90`, ReleaseFast, 1 October 2026 UTC): four R7 circuit proofs passed native verification and matched the pinned Rust `CircuitSerialize` digests. Fibonacci internal/root took 0.766/0.610 s; Blake G internal/root took 0.556/0.560 s. The resident arena was 1.465–1.466 GB. The fixed one-read terminal transport was 3.295 MB, and the device stage times summed to approximately 50–60 ms. These are single runs of standalone circuit proofs, not PIE-to-root pipeline measurements.

Updated problem match: a sub-60 ms device schedule inside a 0.59–0.74 s prove call is primarily a host orchestration and setup problem at this R7 scale. Candidate causes are repeated static preprocessed-tree commitment work, twiddle preparation, per-proof AOT module/context binding, buffer allocation, kernel launch submission, and zero-filling unused terminal capacity. The benchmark must separate these with host wall timers and repeated proofs in one process before ranking them. Cache only topology-static material; keep witness-dependent work and all proof stages resident. CUDA graphs may help the repeated launch sequence, but transcript-dependent kernel arguments and per-proof buffer addresses must remain correct. The packed four-row FRI leaf format was a correctness requirement learned from the CPU/Rust implementation and also cut FRI Merkle tree storage by four.

Next falsifiers: compare first and warmed proof latency in one process; profile host call stacks and CUDA API time, then test cached static commitments/twiddles and reusable device allocations. Run the same four R7 cases after every change. A speedup that changes any Rust digest, adds a proof-stage host read or CPU PCS call, or increases peak memory beyond the target GPU is rejected. The larger wrap/fold circuits and the complete PIE-to-root path remain unmeasured.

Complete-system update (H100 SXM 80 GB, 1 October 2026 UTC): two contiguous mainnet PIEs through Cairo CUDA, two resident circuit wraps, and a resident root fold took 32.308 s from adapted inputs. The final three root files exactly match the pinned Rust reducer. The 51.5/50.9 GB Cairo arena and 28.1 GB circuit arena are planned device extents; peak whole-device memory was not sampled. Peak host RSS was 5.044 GB. A repeat run was interrupted when the GPU host was terminated for exhausted credit, so this is one complete observation.

New measured decomposition: Cairo proof execution/decode itself is 0.467/0.476 s, while each leaf's Cairo ingress is 4.460/3.979 s, with static initialization 2.096/2.064 s. The two circuit wraps cost 6.289/6.290 s, including resident proving 2.328/2.855 s and independent verification 1.702/1.442 s. The root fold costs 9.021 s; 1.475 s is circuit construction, 3.003 s resident proving, and 1.477 s verification. The 44.5-million-variable leaf circuit and the production registry are the scale; standalone R7 Fibonacci results do not predict this cost.

Problem-match brief for the next iteration:

Task and required semantics: Minimize adapted-PIE-to-identical-root latency while every Cairo and circuit STARK remains proved on CUDA and independently verified. Inputs are a contiguous sequence of PIEs, with deterministic root bytes and a dependency edge from both leaves to their fold.

Inputs, measured scale/provenance, encoding, and computational model: two real mainnet PIEs, 70 Cairo queries, 26 PoW bits, one H100 with 80 GB, 32.308 s observed once. The output is exact, not approximate; memory must admit both Cairo and circuit arenas during the in-process verified-leaf handoff.

Constraints, promises, invariants, and exploitable structure: Cairo preprocessing and the registry's circuit topology are static across these leaves; adapted inputs, witnesses, transcript challenges, and proof openings are request-specific. A Cairo proof must verify before a wrap is published, and both wraps must exist before the root fold.

Candidate matches, relationship, and evidence status: (1) batched static-resource reuse is an exact match to amortized preprocessing; the current Cairo app already reuses a runtime/preprocessed snapshot for `--repeat`, but the pipeline launches one process per distinct PIE (sourced from code and receipts). (2) parallel leaf scheduling is a DAG scheduling problem; at the measured 51 GB Cairo arena on an 80 GB H100, concurrent independent Cairo proofs are not yet safely admissible (derived). (3) reducing FRI/commitment kernels is a GPU pass/launch problem, but no production-scale event profile yet identifies a dominant kernel (hypothesis).

Chosen canonical problem and exact variant: First implement amortized preprocessing across distinct, sequential PIE requests in one process, with authenticated Cairo arena keys and a bounded leaf-topology cache. The two Cairo arena sizes differ (51.507 versus 50.894 GB), so they may have different keys; Cairo static reuse is conditional, not a guaranteed 2.064 s saving. Both leaf wraps have the same topology key and 44,505,598 variables, so retaining their shared circuit preprocessing is directly applicable. This cannot by itself yield an order-of-magnitude whole-pipeline improvement. It is lower risk than increasing concurrency before memory admission is measured.

Project-to-canonical mapping and solution recovery: one request equals one batch item; the shared CUDA runtime, same-key preprocessed snapshot, and same-key leaf topology are retained static resources; the verified Cairo callback still emits one byte-identical leaf proof per item. The existing Cairo arena key binds geometry and lifetimes, so a changed shape invalidates its reuse. The leaf cache independently uses the authenticated circuit topology key.

Complexity/limits and prediction: topology preprocessing drops from roughly `O(k * S)` to `O(S + k * D)` for `k` same-topology leaves, where `S` is static circuit construction and `D` is dynamic witness work. Cairo preprocessing only has the same bound for same-arena-key leaves. For these two leaves, the gain is unquantified until a GPU run separates topology cache hits from Cairo arena misses. Reject the change if root bytes differ, peak memory exceeds device admission, or whole-pipeline wall time fails to improve in paired runs.

Correctness and benchmark plan: compare each leaf and all three root files against the current run and Rust, verify no CPU proving fallback or intermediate D2H, measure static/ingress time per leaf and whole-device peak, then profile host setup and CUDA events on the 28 GB circuit proofs. Open uncertainty: whether the retained Cairo arena and concurrent circuit arena leave enough physical H100 headroom for safe one-process batching; use device-memory sampling rather than planned arena sums.

Further exact match, implemented locally pending GPU timing: the circuit preprocessed Merkle root is an immutable commitment. The leaf registry already supplies its authenticated expected root and the fold canonical builder independently computes its root. The prior resident circuit path recomputed that root on the CPU once before CUDA proving and again during native verification. The source handoff now carries the expected root, and the independent verifier checks the GPU proof's committed tree-zero root against it. Standalone R7 fixtures without an expected root retain recomputation. This removes two full host commitment passes per production circuit proof without altering transcript bytes; the remaining falsifier is exact Rust root parity and measured `static_hash`/verification time on the H100.
