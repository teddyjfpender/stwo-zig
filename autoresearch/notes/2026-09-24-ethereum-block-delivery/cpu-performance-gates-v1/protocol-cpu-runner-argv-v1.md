The focused SHA/CPU wrapper now uses `zig_protocol_lib.command.test_command` rather than maintaining a second Zig dependency graph. Package dependencies remain derived from package contracts. A single `interop_postcard` compatibility module points at the same core and proof-wire nodes; canonical protocol roots can import postcard directly. CPU-only composition selects the six existing CPU package nodes with that shared constructor.

Explicit optimization, CPU and strip selections are emitted before every `-M`, including root, packages, postcard and a custom runner's standard-runner module. Custom standard-runner source is resolved from the selected compiler without executing it. Root/default filter behavior, `--all`, explicit Debug, named filters, custom test runner and canonical `--lock`/`--no-lock` semantics are preserved. Builders never take a lock or spawn subprocesses; each CLI retains one lock around its direct Zig invocation. No wrapper invokes another wrapper.

Nineteen pure Python argv/CLI-lock contracts passed via `python3 -m unittest scripts.tests.test_zig_protocol_command scripts.tests.test_focused_cpu_runner`. Subprocess and lock execution are mocked in CLI contracts. No Zig build/test/proof, guest/segment, device or benchmark was invoked. Adjacent JSON records the four owned source hashes.

Historical qualification receipts and their recorded command bytes were not changed. Earlier manual SHA commands explicitly selected ReleaseFast/native for the root, while module-scoped settings reset at later module declarations; their dependency optimization/CPU settings must not be retrospectively labeled ReleaseFast/native. The new argv contracts qualify construction only, not compiler semantics, proof results or a speedup.
