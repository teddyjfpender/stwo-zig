This source candidate adds real CUDA selected-device, stream and dependency-event ownership. It is a prerequisite to routing resident proofs across lanes, not delivered overlap or a performance result. The original proof schedule still has `max_lane_streams = 0`, and NativeSession scheduled admission still requires one physical lane. No CPU driver/cache/readonly, native AOT launch binding, security or proof grammar changed.

`stwo_exec_context_create_options` takes fixed-width version1 options: device ordinal (UINT32_MAX for current device), total lane count1–4 including coordination lane0, and dependency event capacity0–64. NVIDIA construction selects the actual device on the current thread, creates one isolated pool, all requested nonblocking CUDA streams and disable-timing CUDA events before publishing a usable owner. Creation checks exact counts/version/device bounds. Ordinary construction failure unwinds allocated resources and restores the previous device. If CUDA cleanup itself fails, its non-null output is an explicitly teardown-only owner, with the selected device retained for retry. The NEW Zig `Context.openOptions` returns `Construction{ready|failed{cause,teardown?}|released}` and preserves that owner until `Construction.deinit` succeeds. It never turns a partial owner into usable lanes. Callers must retain/move this single owner exactly once and keep its thread/device custody through teardown.

The legacy C constructor remains current-device/one-stream/zero-events and forwards the same native constructor. Existing Zig `Context.open()` retains its error-union interface and retries a retained failed construction cleanup once, as a compatibility path; it cannot transfer a repeatedly failing teardown owner through that old error-union API. Future selected-device NativeSession construction must consume the new owned Construction outcome, rather than use legacy open for additional lanes. This residual legacy fatal-cleanup limitation is explicit, not a failure-atomic claim for that old API.

Every native context operation checks the owning host thread and current device. Native context identity is a monotonic nonzero u64 that rejects exhaustion; each event slot has a monotonic nonzero u64 record generation. Dependency tokens are exactly `{context_identity:u64,generation:u64,slot:u32,producer_lane:u32}`. Native and Zig both assert size24 and offsets0/8/16/20; options are size16 and offsets0/4/8/12. The Zig owned Lane also binds the exact native control identity, lane index and actual stream. Actual `cudaEventRecord` and `cudaStreamWaitEvent` implement record/wait; native validation rejects cross-context, stale, inactive, wrong-lane and out-of-range tokens before use. Slot generation is not reset at a proof boundary, and context identity prevents reuse of a retired control address from accepting an older token.

`releaseDependency` is terminal retirement: it synchronizes all producer/waiter streams before freeing a slot for another record. It is deliberately blocking, with no nonblocking reclamation claim. Terminal `sync` and `join_all_lanes` now join every actual stream. Abort ends the original coordination capture, joins all lanes and invalidates dependency leases before queuing allocation frees; failed frees retain their original registry entry for retry. Destruction joins first, then destroys dependency events, profiling events, streams and pool. Successfully destroyed handles are nulled; a failed destruction leaves a teardown-only native control node and corresponding Zig `teardown_pending` owner. Subsequent ordinary methods reject it; close/abort can retry. Buffer frees for an explicitly multi-lane context also join before freeing on lane0.

Cross-lane capture and graph replay are explicitly rejected. Native graph capture now tracks its actual capture state and admits only one-lane contexts without active dependency leases. Event record/wait/release and lane getters reject capture. CuMetal accepts only its original current-device single lane and zero dependency events; the source does not emulate NVIDIA lane/event operations or compile unsupported wait APIs into that provider path.

These use host sentinels and an API type with NO device methods; they validate actual guards and do not pretend to create a CUDA event/stream/proof.
