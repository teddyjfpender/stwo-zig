## Bounds and custody

Default catalogue metadata is capped at 1 GiB, each local live setup at 8 GiB, cohort rows at 2^24 and nodes at 2^20. Metadata/live lanes retain the aggregate backing independently; scratch is not charged through a hidden metadata cap. Compact inventory is O(N) metadata, initial selected hashing O(N log N) across the batch, and each subsequent selected check O(log N) with fan-in <=4. No whole-job normalization, Fold rows or recursive child capture is retained by these catalogues. Original leaf Scope groups retain only current direct operands/recipes and release after local rows/source compiler teardown. Fixed row/compiler work and original typed leaf admission can still be significant; this is a structural bound, not a measured performance claim.

V20 heap/public/source pointers are stable. On failed owning construction, the caller's local catalogue errdefers retain ownership; successful construction transfers it once. Borrowing never frees the caller catalogues, on success or error. Lower fixed rows use a separate retained live lane and can be released before FINAL22 compilation. Direct key/schedule metadata results retain their actual allocation budget until the final copied schedule is freed. No returned fixed/source object retains a capture. Standalone fresh receivers must independently reconstruct the same exact catalogues and original claim policy once per process; transported IDs do not nominate expectations.
