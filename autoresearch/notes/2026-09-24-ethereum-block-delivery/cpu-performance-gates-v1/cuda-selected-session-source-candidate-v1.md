# Selected CUDA Session construction custody (source candidate)

This batch is source-only and unqualified. The author ran formatting only, no compiler, CUDA C++, device, proof, PCS, segment, guest or benchmark. The previously qualified lane/event metadata and Zig body receipts remain historical; they do not qualify this batch or native C++ hardware behavior.

`session.NativeSession.openSelected(accepted_sms, Selection{device_ordinal,device_uuid})` requires an explicit independently expected ordinal and nonzero UUID. It invokes the genuine selected Context constructor with exactly one physical proof lane and zero dependency slots. Before a ready result, it requires original NVIDIA provider, exact original SM list, platform/device agreement, independent UUID, nonzero build identity, AOT inventory and genuine AOT loader. Original device/SM rejection still occurs before platform probing. `Selection.requireObserved` is a pure metadata validator, never a Session constructor or proof receipt.

`Session.Construction` distinguishes ready, failed with optional `OpeningOwner`, and released. OpeningOwner keeps the actual Context.Construction and any actual AOT loader, on the explicitly assigned runtime owner thread. A loader is destroyed before its context; a nonzero status preserves the pointer and stops teardown. Context cleanup failure similarly keeps its original retry owner. Constructor failure does not implicitly abandon cleanup. Provider mismatch occurs before resource creation. Selected CuMetal construction is rejected: its existing native AOT destroy can report failure after deleting the loader, so retryable custody cannot be promised there.

`process_runtime.NativeRuntime.openSelected` is the consumed process-runtime entry. It acquires the existing single-owner registry, transfers a ready Session into the actual runtime, or retains a failed Session.Construction plus registry lease in its typed outcome. Failure without any resources releases the lease immediately. Failed cleanup retains the lease; only successful terminal cleanup releases it. Wrong-thread lease cleanup is rejected. No per-device concurrent registry or multiGPU concurrency is introduced.

Original Session/Runtime close and abort now stop on teardown errors while preserving retry custody, including caches and loader. Successful loader destruction followed by failed context destruction can be retried without reusing the destroyed loader. A Session in teardown cannot begin another proof or prepare an execution. Original Runtime abort no longer marks itself closed or releases the process lease after failed Session cleanup. The original finish path shares the same terminal close implementation. A completed externally borrowed Session is recognized only on its actual owner thread before registry release.

Compatibility `Session.open` and `ProcessOwnedRuntimeFor.open` retain their error-union signatures and current-device semantics. Those APIs cannot convey a repeatedly failing construction cleanup owner; compatibility Context open performs only its original cleanup attempt. New selected callers must use the typed outcome and retain it until deinit succeeds. Existing generic runtime users without Session.Selection/Construction retain their original API (the new Construction declaration is statically absent/void). The new selected API is not enabled by a CLI/default here.

The seven authored behavioral fixtures use an API-free specialization to check independent metadata, rejected capabilities/provider, empty cleanup ownership, retained negative address metadata on repeated failure, failed registry lease thread guards and the actual registry's repeated no-resource rejection path. No fake CUDA API, successful Session, event, stream, loader or proof is created. OutOfMemory tags only check retention of an original failure cause; there are no new host allocations to inject, and neither native OOM nor successful/repeated native destruction is simulated. Actual native OOM and cleanup behavior remains unqualified.

The separate object/semantic-only root retains six genuine NativeSession/NativeRuntime constructors, cleanup, terminal and compatibility exports; they must never be executed by host tests. Native .cu/.h and AOT C++ dependencies are explicitly pinned because literal Zig traversal does not include them. The existing option/token layout assertions in native and Zig remain unchanged.

Remaining runtime routing: AOT functions, immutable module globals and graph-cache replay still bind lane0; proof scheduling remains `max_lane_streams=0`. Actual dispatcher event dependencies, per-lane launch receipts/globals, multi-context/prefetch queues, aggregate scratch admission and per-device concurrent registry are still separate work. No overlap, speed, hardware availability or security/completion claim is made.
