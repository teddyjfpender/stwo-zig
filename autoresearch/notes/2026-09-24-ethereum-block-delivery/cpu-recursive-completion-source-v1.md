# Selected CPU recursive completion

The installed `stwo-ethereum-block-v5-cpu-produce` entry accepts an optional
`--recursive-completion` after its existing six positional arguments:

```text
stwo-ethereum-block-v5-cpu-produce ELF INPUT ORACLE MAX_SEGMENT_CYCLES JOB_ID_HEX OUTPUT_DIR --recursive-completion
```

This source path uses the genuine typed capacity stack and canonical 70-query,
26-PoW configuration. It selects recursive family publication and original
source PAGE publication, then drives one bounded completion pipeline:

```text
native/fused/caller/ROM/lookup files -> requester-only scoped forest
                                             |
                                             | original verifier rows + public compensation
                                             v
                                          PUBLIC21 --------+
                                                          |
source PAGE files -> PAGE forest --+                       |
                                  +-> memory root V20 ----+-> FINAL22
RAM + range files -> RAM forest --+
```

The requester forest excludes RAM/range providers and exports the original
packed transition value. Public compensation preserves original register,
state, ROM and accounting equations. FINAL22 verifies exactly two genuine
recursive roots and closes the original signed requester/memory transition
relation and supplier schedule. Each expected key is reconstructed before
stored manifest proposals are compared against it.

One aggregate allocator covers all selected completion stages. Current child
captures are released after verifier rows own their inputs; consuming workers
release source columns at their original last use. The requester root capture
is released after PUBLIC21 rows are independently owned. Normative catalogue
metadata and authenticated source owners remain alive through final receiving.
PAGE and memory owners transfer only on successful typed builder completion.

Original memory limits are derived from the collection policy and checked
before collection. Selecting this completion alongside the old all-family
`scoped_job`, without recursive family publication, without source PAGE
publication, or without register-local windows fails before guest/proof work.

Publication is exclusive. A scoped-fold transaction tracks successful node
files before invoking observational callbacks, and rolls back its prefix on
failure. The cross-stage coordinator removes only newly published completion
files if a downstream stage fails, including manifests. Original proof inputs,
original PAGE policy, pre-existing destinations and unrelated recipes remain.

The JSON report includes `recursive_completion_selected` and the selected
completion report: proof counts/bytes, durable final manifest pin, allocator
peak and requester/PAGE/memory/final stage nanoseconds. Stage times include
setup, proving, encoding/file staging and fresh receiving; they are not
isolated STARK timings. These fields are source instrumentation, not new
performance measurements.

Qualification currently consists of nonproving policy/transport/OOM fixtures
and compilation/retention of actual producers, receivers and installed entry.
Segments, guest/STARK and device runs remain stopped. This path still uses
instance-specific setup reconstruction and keeps the original full detached
bundle verification. It does not emit a standalone CompleteBlock authority.
Complete independently admitted fixed setup/public source ports, full global
closure audit, canonical default activation and positive end-to-end proving
with process peak-memory/time qualification remain required.

Authoritative qualification receipts and immutable attempt snapshots are in
`cpu-performance-gates-v1`; the implementation ledger records each cohort and
its actual evidence scope. A source-only body marker is never a positive proof.
