# Native projection and ordinary memory fusion v2

Canonical source integration and nonproving qualification are complete for
this slice. Execution segments, STARK jobs and block benchmarks remain stopped;
joint proof acceptance, complete bundle verification and performance are still
unqualified.

The canonical warm `block_v5_native_projection_fused_stage_v2` replaces the
separate program/native projection and ordinary memory callbacks. It shares
the authentic native fixed/main prefix, reconstructs the existing bounded
ordinary access traces, recommits the collected access witness, and compares
its root and exact byte-counter snapshot before producing one local STARK.
The independently verified native-v3 base AIR remains separate.

For nonempty ordinary RW schedules, the local STARK has four trace trees:
fixed, main, access witness and one interaction tree. Projection and memory
components accumulate into one composition polynomial and FRI. The projection
adapter maps its original interaction tree to index three and inserts an empty
witness declaration; it preserves every original opening. Its root owner's
main mask is the union of all projection and access source cells. The access
adapter delegates every existing integer/carry, transition, positive byte
query and opposite universal memory constraint and mask. A shared composition
split does not increase the access component's own quotient evaluation degree.

One canonical v2 identity includes the word protocol ABI, native template and
instance, fixed/main roots, execution ordinal, exact frame, access witness root
and both exact ordered schedules. The ordinary family3 entry remains the
existing packed sidecar commitment. The shared PCS transcript consumes the
universal47 and word suffix before the v2 proof domain and all claims.

The receiver reconstructs both schedules from independently admitted native
shape and frame. It fresh-verifies native and the joint STARK, or accepts the
private immediately-fresh-native callback seam. It returns separate optional
program/six-table/state/register/clock and ordinary packed/universal/byte
receipts. These claims remain open until the complete receiver closes every
global provider, register window, caller and recursive obligation.

Zero RW uses the existing freshly admitted EmptyOpcode policy and a genuine
projection-only three-trace-tree proof; there is no access tree or memory
receipt. If both exact schedules are absent, the genuine native base proof
still verifies, no local STARK is loaded, and both local receipts are null.
An unexpected STARK, missing real projection proof, changed witness/frame or
old v1 identity rejects. No zero scalar or dummy STARK replaces an obligation.
