# Native-v3 mainnet recursive bounds, read-only audit

This source audit establishes no deterministic recursion failure for the 2M-cycle, 67-leaf schedule. The actual canonical native proof geometry, recursive hash-row census and peak allocations for those leaves are not yet measured. Small-fixture process RSS does not establish that the mainnet recursive worker fits its cap. No source changes or builds were performed for this audit.

`Layout.fromCounts` adds transcript and authenticated Merkle-path G/XOR rows, then rejects either ceiling-log above 24: more than **16,777,216 rows** in either cohort produces `InvalidNativeHashLayout` ([blake3_native_hash_layout.zig](../../../src/frontends/riscv/recursion/blake3_native_hash_layout.zig#L27)). This happens before the later G partition ([blake3_g_partition.zig](../../../src/frontends/riscv/recursion/air/blake3_g_partition.zig#L17)); partitioning cannot rescue an already rejected layout. The actual 2M-leaf census is unknown, so this is a concrete threshold, not a predicted failure.

The standalone producer uses a **40GiB outer tracked budget**, with both the cache and its worker capped at **16GiB** ([ethereum_block_v5_cpu_produce.zig](../../../src/frontends/riscv/ethereum_block_v5_cpu_produce.zig#L19), overrides at line 48). The cache creates its budget from the driver allocator and passes that budget's allocator into worker construction ([setup cache](../../../src/frontends/riscv/prover/block_v5_native_recursive_setup_cache_v1.zig#L41), worker construction at line 147). The worker creates its own budget over that allocator ([worker](../../../src/frontends/riscv/recursion/blake3_native_parent_worker.zig#L38)). These nested caps account for the **same allocations**; they do not supply an additional 32GiB allowance. Stacks, allocator overhead and external backend allocations are outside tracked byte accounting.

Native capture and `Bus.prepare` source rows use the outer allocator, outside the cache's cap ([leaf stage](../../../src/frontends/riscv/prover/block_v5_native_recursive_leaf_stage_v1.zig#L75), rows at line 84; [Bus.prepare](../../../src/frontends/riscv/recursion/block_v5_recursive_public_bus_v1.zig#L145)). The cache calls the nonconsuming `worker.proveAdmitted` ([cache lease](../../../src/frontends/riscv/prover/block_v5_native_recursive_setup_cache_v1.zig#L70)), so these rows remain live through recursive proving and still count against 40GiB. A consuming worker API exists ([worker](../../../src/frontends/riscv/recursion/blake3_native_parent_worker.zig#L79)); changing ownership is outside this audit.

The cache permits exactly one entry. Hits require equal context/configuration, public routing digest and validated fixed-row fingerprints; misses evict the old entry before constructing its replacement ([setup cache](../../../src/frontends/riscv/prover/block_v5_native_recursive_setup_cache_v1.zig#L118), eviction at line 135). Native template identity binds total steps, external retirements, and each component/infra descriptor's exact active `n_rows`, not just padded logs ([geometryDigest](../../../src/frontends/riscv/prover/block_v5_native_template_protocol_v3.zig#L55)). Repeated padded geometry therefore does not guarantee cache hits across the 67 leaves. Misses require cold setup but do not by themselves cause an admission or resource failure.

The earlier two-ADDI q8 cache gate measured 390,119,752 cache-owned peak bytes, explicitly excluding borrowed native captures/source rows and subsequent receiver allocations ([qualification JSON](block-v5-native-recursive-stage-cache-q8.json)). Neither that measurement nor whole-process tiny-fixture RSS predicts the actual canonical mainnet worker peak. Remaining capacity outcomes require the actual census and allocation evidence; this audit does not establish that 16GiB is sufficient or insufficient.
