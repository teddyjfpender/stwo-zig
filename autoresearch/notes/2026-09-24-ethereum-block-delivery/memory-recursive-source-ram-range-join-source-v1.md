This batch is source-only and unqualified. No compiler, test, STARK, guest,
segment, benchmark or device execution was run by its author. Formatting and
literal dependency hashing do not qualify any proof equation.

space1 RAM-lane and range16 leaf verifiers. It does not construct `Fresh` or

## Actual API

- `Provider.ForKind(.ram/.range).verify(a, Policy, bytes)!*Fresh` calls the
  original genuine Leaf verifier before creating its source. Independent
  native Prepared policy, key/id, public schedule and original OpenReceipt
  proposal outlive Fresh. `Source.init(*Fresh)` borrows its owner.
- `Public.Owner.init(a, Policy{source,*independent lane Pins,ram[],range[]},Limits)`
  owns bounded source arrays and original range plan while borrowing all genuine
  captures/independent policies. `deinit` releases its retained aggregate budget.
- `Preparation.prepare(backing,*Owner,transcript_capacity,Limits)!Prepared`
  embeds each original child verifier through original `State.plan`, then
  attaches the actual join graph using the same scalar/arithmetic lowerer and
  cohort recipes. Namespace/key/graph/transcript identity is version-bound.
- `Producer.ForBackend(CPU).deriveKey/init/proveEncodedConsuming` uses original
  fixed setup, consuming parent worker and strict original parent codec under
  the new Admission. Derivation is a key proposal. Producer output gains no
  fresh-verification authority; Receiver does actual original Parent.verify.
- `Receiver.verify(a,Policy,bytes)!*Fresh` independently reconstructs the public
  owner and verifies the new parent. Its independently supplied children must
  themselves already be genuine Fresh captures; durable reconstruction of this
  whole child hierarchy is a separate production integration obligation.

All input policies/captures outlive their borrowing public owners, workers and
verification. Prepared owns its bounded child-row/cohort output and copied wire
schedule; original consuming proving releases rows before FRI, with idempotent
error teardown. The test fixtures never invent a capture to exercise this API.

## Deliberate fan-in bound and remaining architecture

`MAX_CHILD_VERIFIERS=4` is a HARD protocol admission limit, including the PAGE
root. Enlarging caller resource limits cannot bypass it. The rejected >4 census
fixture checks this before touching any policy. This is a genuine bounded
small-instance join, not scalable canonical block assembly: a PAGE root plus
85 RAM captures and4 ranges cannot be put into one parent.

Required next architecture is a shard-local RAM/range aggregation forest, with
at most4 actual verifier captures per node, conserved per-shard deficits/counts,
exact leaf ranges, closed internal recursion-wire suppliers, compact authenticated
summary coordinates and a final PAGE-root + aggregate join. Reuse this algebra;
do not pool or omit shards, infer execution spans, or carry host-verified sums.
Bounded child replay/transport and complete transition hooks remain separate.
