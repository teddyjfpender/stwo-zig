# RISC-V frontend soundness audit (October 2026)

**Captured:** 2026-10-16 to 2026-10-18

**Revisions audited:** `55cc2698f` (first pass), `f8b64e96b` "Harden proof
verification and RISC-V frontend soundness" (second pass), plus the
follow-up changes described in "Second-pass fixes" below.

**Scope:** the `stwo-zig-riscv-cpu` product routes (legacy Blake2s JSON
artifact verify route, authenticated lookup V2, the default BLAKE3 execution
artifact route `B3RVART1`/`B3EVART1`/`B3PVART1`, CSP-ECDSA, guest profile) and
the native AIR, prover and verifier behind them. The Poseidon2 recursive RISC-V
verifier (the "recursion lane") is out of scope: it is declared not qualified
in `soundness/RISCV_FRONTEND_VERIFICATION_STATUS.md` and is not reachable from
any product command.

**Method:** six scoped read-only review lanes over two passes (global AIR
invariants and buses; constraint compiler, lookup tables and Word32/M31 sites;
runner, ELF loader, host interface and precompiles; verification of landed
fixes plus the BLAKE3 route; segments, public I/O and Poseidon2 wiring), each
reporting only findings confirmed by reading every enforcing path or by an
executable proof of concept. The lead independently re-read every Critical
before a fix was started. Fixes were made by separate engineers with negative
tests and the focused and full product suites re-run.

This record is evidence for the ledger. It does not change
`whole_frontend_verified = false` or `proof_system_soundness = false`.

## Headline

Five Critical forgery paths in the native proof route were found and closed,
plus one High and several Medium hardening items. All fixes change the proof
transcript or the AIR, so every RISC-V proof produced before `f8b64e96b` is
incompatible with the current verifier, and the recursion lane's committed key
and bundle artifacts are stale.

Verified sound after the fixes (file references are to the current tree):
Fiat-Shamir order and claim binding on every product route; memory and
register bus ordering (20-bit clock-gap range checks, clock-update wrap
protection); public register boundary and x0 handling; program lookup bound to
the ELF text root; range-check tables regenerated by the verifier; sparse
Merkle memory commitment including node multiplicities, row sign and public
roots, and the atomic node-to-hash binding; segment V2 entry/exit authenticated
wire; V1 public I/O words; Poseidon2 AIR lanes and degree; secp256k1 recovery
arithmetic given a sound byte table; Keccak-f AIR; ELF header and section
parsing; step cap versus clock encoding; traps and completions fail closed.

## Findings and dispositions

Severity: Critical = an accepting proof of an execution that did not happen or
of different public I/O; High = weaker-than-claimed binding with a plausible
exploit; Medium = robustness, completeness or claim mismatch.

### Critical (all fixed)

| Id | Defect | Where (before fix) | Fix (current tree) |
| --- | --- | --- | --- |
| A-F1 | Per-batch LogUp claimed sums were never mixed into the transcript; only 28 aggregates were. Components consumed per-batch claims straight from the proof, so after the OODS point a prover could shift a value between two batches of one component and satisfy the composition check for any statement. | `air/transcript/claims.zig` `InteractionClaim.mixInto`; `air/statement.zig` `canonical`; `proof_transcript.zig` `mixInteractionClaim`; `air/lang/lookup_physical_manifest_v2.zig` `AuthenticatedStatement.mixInteractionClaim`; `prover/base_component_assembly.zig` claim plumbing; `air/lookups/opcode_component.zig` `pairConstraint`. | `air/statement.zig` `mixShardManifest` (shape prefix) and `mixPhysicalClaims` (every opcode batch claim and every infra claim, domain words `STWP`/`PCL1`), called canonical-first then physical from both `mixInteractionClaim` paths. The BLAKE3 route already mixed all claims (`prover/blake3_execution_protocol.zig` `mixClaims`). Negative tests: `proof_transcript.zig` unit test; `src/tests/riscv/malicious_prover_harness.zig` end-to-end shift. |
| A-F2 | Merkle node child multiplicities were constrained only by `v(v-1)(v-2)=0` independently of the parent, so a leaf could be emitted twice and a word could carry two access chains (stale loads, forged public output). The boundary table had no in-AIR clock constraint. | `air/memory_commitment/merkle_node.zig`; `air/memory_commitment/interaction.zig`. | `lhs_mult·(lhs_mult−cur_mult)=0`, `rhs_mult·(rhs_mult−cur_mult)=0` in `merkle_node.zig` and typed twin; `m·(m+1)·clock=0` and row-sign-to-public-root binding through verifier-owned `RootParameters` in `interaction.zig`, plumbed via `air/component.zig` and `prover/base_component_assembly.zig`; negative tests in both files; focused step `test-memory-commitment-soundness`. |
| B-P1 | A Merkle node requested its Poseidon2 hash as two separate lookup terms (input, output) on one relation, so one hash row's output could be paired with another row's input. Executable proof of concept opened an RW or program-ROM leaf with a forged value under an honest root. | `merkle_node.zig` `entriesGeneric`; `air/memory_commitment/poseidon2_wide_equations.zig` row pairs. | One atomic `poseidon2_io` tuple `[lhs, rhs, 0×14 ‖ cur, 0×15]` per node, matched by the hash row's narrow input/output tuple (`poseidon2_layout.zig` `narrowIoTuple`), applied to every product-reachable Poseidon layout (`poseidon2_wide_equations.zig`, `poseidon2_air.zig`, `poseidon2_narrow_degree3_v1.zig`, `poseidon2_universal_equations_v1.zig`), typed twins, goldens and Metal rosters regenerated. | C-C1 | secp256k1 byte range-check table: inactive rows had an unconstrained value yet were emitted with free multiplicity, voiding every limb range check in the recovery precompile. | `air/guest_precompile/secp256k1_component_config.zig` `ByteTable`. | Bits boolean and value reconstruction unconditional on every row. Negative test in `tests/secp256k1_component_test.zig`. |
| C-C2, C-C3 | secp256k1 signed-digit table entries not bound to their digit codes (negative rows never consumed their positive entry; chain rows did not tie `prev.code`), and the scalar program's doubling transition kind was a free witness column, so a doubling could become a no-op. | `secp256k1_table_direct.zig`; `secp256k1_scalar_direct.zig`. | Negative rows consume `(kind, code−8, positive, source)`; chain rows constrain code and kind continuity; doubling slot kind constrained to the legal set. Table tuple carries a per-call source identity (C-H1). Negative tests in the `tests/secp256k1_*` files. |

### Medium

| Id | Item | Status |
| --- | --- | --- |
| C-M1 | Keccak-f caller admitted state pointers congruent to 4 mod 8 through an M31 wrap in the alignment encoding. | Fixed: `keccakf_caller.zig` composes the last double-word index so `8·dwi` cannot wrap. |
| C-M2 | Scalar multiplication had no equal-points case; a submitter could choose `R = kG` so an add slot met its own table entry and the recovery could not be proven (per-request hosted-prover denial). | Fixed: `add_equal` point kind (`secp256k1_point_direct.zig`, `secp256k1_affine.zig`) with positive and negative tests. |
| C-M3 | ELF `p_memsz` unbounded (hosted-prover memory exhaustion). | Fixed in `f8b64e96b`: `runner/elf_loader.zig` `MAX_LOAD_IMAGE_BYTES` preflight. |
| B-M1 | Register-file byte invariant is load-bearing for the load/store and jalr address bounds (`fixed_load_store.zig` relies on `rs1[3]` being a byte; limbs 1 and 2 are not range-checked there). Inductive via every register write being range-checked and the initial state being bytes. | Open; recommended either an explicit `range_check_8_8` on the address-source limbs or a named global lemma under FV-4. |
| B-M2 | Inactive-row behaviour is outside the Lean theorems (`air/extract/program.zig` fixes `is_active = 1`); verified by hand that every use-side numerator is zero on inactive rows. | Open; recommended exporting `is_active` in extraction plus a lemma. |
| A-F2b | Boundary table has no strict address ordering in-AIR. With A-F2 each leaf tuple is emitted at most once per root emission, so a word has at most one boundary row per sign; assessed not exploitable. | Open hardening (needs a next-row main mask). |

## Second-pass verification results

- All first-pass fixes hold under independent re-reading; the default BLAKE3
  route's memory commitment uses a verifier-owned schedule with preprocessed
  direction weights and strictly increasing addresses, so it has neither the
  multiplicity nor the sign/root gap.
- `zig build test-riscv -Doptimize=ReleaseSafe -j2`: green at `f8b64e96b`
  (3600 of 3626 passing, 21 skipped, 0 failed after the inventory
  restoration) and green on the final follow-up tree (exit 0; the
  recursion-lane key pin is skipped, see below).
- `zig build test-riscv-prover -Doptimize=ReleaseSafe -j2`: exit 0 on the
  final tree, 0 failed, 37 skipped. The 15 previously failing tests were harness drift (corpus traces
  appended across programs after `Trace.append` began enforcing consecutive
  clocks; a legacy load/store test oracle missing the aligned-address columns;
  pool-audit counter pins; a zero-bit proof-of-work instrumentation asymmetry;
  and the unqualified recursion leaf test, now opt-in through
  `STWO_RECURSION_RUN_UNQUALIFIED_LANE=1`). None was a tampered witness being
  accepted.
- Test inventory: 870 files named, 37 excluded with reasons; 159 previously
  never-compiled test files now run.

### Independent finding in the recursion lane

**R-F1 (Critical for the lane, not product-reachable):** the recursion's
universal Poseidon2 provider shell (`recursion/air/universal_shared_provider.zig`
selects `.universal`; `air/memory_commitment/hash_component.zig`
`poseidonGeneralConstraintsGeneric` adds no mode constraint) admits narrow rows
whose atomic tuple `[in16 ‖ out0, 0×15]` satisfies any full-IO request whose
output lanes 1 to 15 are zero. Full-IO requesters with free output columns
include the transcript sponge, trace and FRI Merkle rows and the public-claim
hashes (`recursion/air/transcript_air.zig`, `trace_merkle.zig`,
`fri_merkle_leaf.zig`, `merkle_path.zig`, `fri_merkle_node.zig`,
`vm_public_claim_hash.zig`, `vm_public_io_hash.zig`). A prover could zero most
query words and challenge limbs per draw. Fix: constrain `enabler·(1 − io) = 0`
in the universal shell (or domain-separate the narrow tuple) and re-pin the
provider authority digest and seals. Native exposure was checked: the product
hash component runs the `narrow_memory` shell, which pins `wide = io = 0`, and
every native requester (the Merkle node and the guest Poseidon2 caller,
`air/guest_precompile/component_registry.zig:571` `provider_narrow_output`)
requests the narrow tuple, so no native collision exists; the Ethereum
memory-commitment node (`air/memory_commitment/ethereum_node_v1.zig:166`)
should be confirmed to request the narrow shape as part of the re-alignment.

Follow-through: the full-IO constraint is implemented in the wide and compact
provider shells, with changed constraint counts and new authority/semantic
digests. The focused provider suite passed (235 passed, one skipped). This
closes the local row forgery; the required end-to-end G-3(d) recursive-proof
rejection is still pending.

The detached SegmentV2 leaf key now carries the native Tree0 root and the
standalone CPU verifier regenerates it from admitted native descriptors before
reading proof bytes. A positive/changed-root test passes. This does not yet
discharge K-8 for parent keys or the older frozen V1 row-5 source.

The recursive AIR source-map check is not current: its pinned SHA-256 values
already differ from eight live source files, including the compact Poseidon
implementation, field arithmetic, framework interaction and Lean axiom audit.
Those mappings require equation-by-equation review before re-pinning; changing
hashes alone would not be soundness evidence.
